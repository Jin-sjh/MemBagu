# 离线与在线流水线

## 【问题】
RAG 一般分为离线和在线两步，这两步各自负责什么？

## 【回答】
RAG 把"建索引"和"回答"拆成两条职责不同的链路：

- **离线（Offline）**：负责把**非结构化知识变成可检索的索引**，依次做**解析 → 清洗 → 分块 → 嵌入（Embedding） → 建索引**，并承担后续的**版本管理与增量更新**。
- **在线（Online）**：负责**理解用户意图、检索、融合、约束生成**，并保证**延迟与成本可控**，典型流程是 Query（可选改写） → 检索 →（可选重排） → 拼装 Prompt → LLM 生成 →（可选）引用出处与评估回流。

一句话：**离线决定"能不能被搜到"，在线决定"搜得准不准、答得快不快"**。

## 【问题】
为什么说离线和在线要分开设计，而不是一条流水线走到底？

## 【回答】
因为两阶段的**瓶颈与优化目标不同**：

- 离线可以**慢、可以批处理**（大批量嵌入、建 ANN 索引、跑版面分析），目标是**索引质量与覆盖**；
- 在线必须**低延迟、可控成本**，只能做轻量操作（Top-K 检索、小范围重排、拼 Prompt），不能把离线重活搬到用户请求里。

**生产环境应对 chunks 批量嵌入并缓存；检索应用 ANN 索引，不要暴力两两算相似度**，否则在线延迟不可接受。
