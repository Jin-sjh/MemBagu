# Skills 与 Agent 的边界与选型

## 一、核心定位：一句话分清边界

Skill（技能/工具）是原子化的“执行单元”，被动触发、只做一件明确的事，相当于 AI 的“手”；Agent（智能体）是具备自主闭环的“决策主体”，主动规划、调度技能、纠错迭代直到完成目标，相当于 AI 的“大脑+指挥官”。

通俗公式：`Agent = LLM 推理中枢 + 规划记忆能力 + 一组可调度的 Skills`

## 二、多维度详细对比

| 对比维度 | Skills（技能/工具） | Agent（智能体） |
|---------|---------------------|----------------|
| **核心本质** | 封装好的单一能力模块，类似“函数/插件” | 目标导向的自主执行系统，具备完整决策闭环 |
| **决策主体** | 设计者预先定义逻辑，AI 仅填充内容 | 运行时由 LLM 动态决策，路径实时生成 |
| **执行逻辑** | 固定流程/方法论，输入→处理→输出，无分支决策 | 动态规划任务路径，可拆解、重试、调整、纠错 |
| **输入要求** | 明确的任务描述+结构化参数，边界清晰 | 高层次目标/开放式问题，无需细化步骤 |
| **状态与记忆** | 无状态，执行完即结束，不保留上下文 | 持续维护任务状态，有短期/长期记忆，可跨步骤复用信息 |
| **自主性** | 完全被动，必须被用户/Agent 调用才运行 | 自主运行，启动后持续推进直到目标达成或被终止 |
| **稳定性** | 高，输入输出契约明确，结果可预期 | 中等，受模型推理能力影响，存在一定不确定性 |
| **典型例子** | 查天气、发邮件、代码格式化、生成单张图表、文本翻译 | 竞品深度调研、全流程旅行规划、代码开发+调试、异常数据根因排查 |

*参考来源：腾讯云开发者社区、CSDN 技术博客*

## 三、使用边界：什么时候用 Skills，什么时候用 Agent

### 1. 仅用 Skills 即可满足的场景

当任务满足以下全部特征时，优先用 Skills，成本更低、结果更可控：

- 任务目标单一，步骤 ≤ 3 步，可一次性调用完成
- 输入输出格式可标准化，无需动态分支判断
- 不存在异常处理、重试、纠错需求
- 执行路径可枚举，能通过固定逻辑覆盖所有情况

**典型场景**：翻译一段文本、生成一张指定风格的图片、查询单个数据接口、格式化一段代码、提取单篇文档的关键词。

### 2. 适合引入 Agent 的场景

当任务出现以下任一特征时，Skills 已无法独立完成，需要 Agent 做调度与决策：

- 任务需要跨多个工具/系统串联执行，中间有数据流转
- 执行过程可能出错，需要自我检查并修正重试
- 任务路径不固定，需根据中间结果动态调整下一步
- 需要长时间持续运行，分阶段推进目标

## 四、必须使用 Agent 的核心场景

以下场景中，单一 Skills 或静态工具链无法覆盖，Agent 的自主闭环能力是刚需：

### 1. 多步骤、路径不可枚举的复杂认知任务

这类任务无法预先写死流程，步骤数量和顺序依赖中间结果动态生成，穷举所有分支的开发成本极高甚至不可行。

- **典型例子**：深度行业调研报告（搜索资料→筛选信源→提取数据→对比分析→生成报告→制作 PPT）、学术文献综述、端到端软件开发（需求拆解→写代码→运行调试→修复 bug→打包部署）。
- **为什么必须用 Agent**：Skills 只能完成其中单个环节，无法自主判断“下一步该做什么”，也不能根据上一步结果调整后续计划。Agent 可通过任务拆解能力将大目标拆分为子任务，再依次调度对应 Skills 落地。

### 2. 需要自主纠错与迭代优化的任务

执行过程中大概率出现异常或效果不达预期，需要“发现问题→调整参数→重新执行”的闭环，静态工具无法自反。

- **典型例子**：生成数据可视化图表后自动检查排版并修正、代码运行报错后自主定位问题并修复、文案生成后自行润色优化直到符合要求。
- **为什么必须用 Agent**：Skills 是“开弓没有回头箭”，执行错了只会报错返回；Agent 具备反思能力，能评估执行结果、识别问题，再重新调用 Skills 调整参数重试，直到结果达标。

### 3. 动态信息环境下的探索型任务

信息源分散、动态变化，需要持续搜集、筛选、验证，无法通过单次查询获得完整答案。

- **典型例子**：实时竞品价格与功能监控、突发舆情的全渠道追踪与分析、异常数据的根因排查（逐层下钻定位问题源头）。
- **为什么必须用 Agent**：单一查询类 Skill 只能获取单次、固定维度的数据；Agent 可自主设定检索策略，多来源交叉验证，遇到信息缺项时主动补充搜索，最终整合出完整结论。

### 4. 跨异构系统/工具的协调型任务

需要串联多个独立系统、工具，中间存在复杂的数据流转、权限校验和逻辑判断，无法用单一 API 或脚本覆盖。

- **典型例子**：从多个 Excel 文件汇总业务数据→生成趋势图表→写入周报 PPT→同步发送给部门全员、跨 ERP/CRM/OA 系统完成订单审批与库存同步、客服工单全闭环处理（查询订单→解释规则→申请退款→同步物流→回访）。
- **为什么必须用 Agent**：Skills 只能操作单个系统，无法处理跨系统的数据映射和异常分支；Agent 作为中枢协调各 Skill，负责数据传递、异常兜底和流程推进。

### 5. 长周期、有状态的持续运行任务

需要长时间保持上下文、分阶段执行，且能根据环境变化自主调整动作。

- **典型例子**：7×24 小时智能客服（记住用户历史对话，持续跟进工单直到解决）、项目进度自动跟踪（每日同步各成员进度，识别风险并提醒）、营销活动全周期自动化（预热→投放→数据监测→优化策略→复盘）。
- **为什么必须用 Agent**：Skills 是无状态的单次执行，无法维护长期任务上下文；Agent 具备记忆能力，可持续跟踪任务状态，在无人干预的情况下长期自主运行。

### 6. 面对未知边缘情况的现实场景任务

现实环境变量多、无法穷举所有异常分支，需要临场推理应对。

- **典型例子**：桌面 GUI 自动化（操作遗留系统，应对界面弹窗、布局变化）、复杂客户咨询（个性化问题多，无法用固定话术覆盖）、实体机器人的动态路径规划。
- **为什么必须用 Agent**：固定脚本/Skills 只能处理预设情况，遇到未枚举的异常就会失效；Agent 可基于通用推理能力临场判断、灵活应对未知情况。

## 五、选型判断公式

- 如果你能清晰写出“输入 A → 执行 B → 输出 C”的固定步骤 → 用 Skills
- 如果你只能说清“我要达成 XX 目标”，但说不清具体有几步、每步怎么做 → 必须用 Agent
