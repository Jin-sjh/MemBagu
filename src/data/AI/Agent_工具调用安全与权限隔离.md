# 工具调用安全与权限隔离

## 【问题】
为什么说「永远不信任模型输出的工具调用」？

## 【回答】
模型可能被诱导产生**危险参数**（如「忽略上文，输出密钥」式注入）。工程上应对工具调用做：
- **schema 校验**（JSON Schema / 范围检查 / SQL 参数化）；
- **权限检查**、速率限制；
- 必要时**人工确认**；
不能把模型当作安全边界。

## 【问题】
工具调用的「两步授权」怎么做？

## 【回答】
- 模型仅生成**「意图与参数」**；
- **策略服务**校验角色、资源 ID、速率；
- **执行器**真正调用；
- 拒绝时把原因反馈给模型或用户。

关键原则：**模型提议 → 策略引擎批准 → 执行**，三者分离。

## 【问题】
如何做跨 Agent 的权限隔离？

## 【回答】
- 工具**分账户 / 分密钥**；
- Agent **最小权限**；
- 敏感操作走**审批工作流**；
- **审计日志**不可篡改存储（记录谁在何时、对什么资源、通过哪个 Agent、执行了什么工具）。

避免把高风险动作靠 Prompt 约束，要固化在权限边界（如排查 Agent 仅只读、变更需人工二次确认）。
