# 设计提示的通用技巧

## 【问题】

设计提示词有哪些通用技巧？

## 【回答】

设计提示词是一个**迭代过程**，需要大量实验才能获得最佳结果。核心技巧包括：

1. **从简单开始**：从简单提示词开始，逐步添加元素和上下文；涉及多子任务的大任务应**分解为更简单的子任务**逐步构建，避免一开始就添加过多复杂性。
2. **使用指令**：用命令指示模型执行"写入、分类、总结、翻译、排序"等简单任务；用不同关键词、上下文和数据实验不同指令，**上下文越具体且越相关效果越好**。
3. **保持具体**：**提示越具描述性和详细，结果越好**；不存在特定词元或关键词能保证更好结果，更重要的是**格式良好、描述性强的提示**，在提示中**提供示例**对获得特定格式的期望输出非常有效。
4. **避免不明确**：具体直接通常更好，类比有效沟通——**越直接，信息传达越有效**。
5. **说"要做什么"而非"不要做什么"**：避免说不要做什么，而应**说要做做什么**，更具体并聚焦于有利于模型生成良好回复的细节。

## 【问题】

如何用清晰的定界符组织提示词的指令与上下文？

## 【回答】

有些人建议将**指令放在提示的开头**，另有人建议**使用像 `###` 这样的清晰分隔符**来分隔指令和上下文。例如：

```
### 指令 ###
将以下文本翻译成西班牙语：

文本："hello！"
```

输出：`¡Hola!`

## 【问题】

设计提示词时，为什么要具体并控制长度？

## 【回答】

**要非常具体地说明希望模型执行的指令和任务**，尤其是对生成结果或风格有要求时。不存在什么特定的词元或关键词能确定带来更好的结果，更重要的是**有良好格式和描述性的提示**。同时要注意**提示长度有限制**，应思考需要多具体详细——**包含太多不必要的细节不一定好**，这些细节应相关且有助于完成任务。示例——从文本提取特定信息的提示：

```
提取以下文本中的地名。

所需格式：
地点：<逗号分隔的公司名称列表>

输入："...里斯本未知的香帕利莫德中心的神经免疫学家 Henrique Veiga-Fernandes 说：..."
```

输出：`地点：里斯本，香帕利莫德中心`

（输入文本来自一篇 Nature 文章。）

## 【问题】

提示词不明确会导致什么问题？如何改进？

## 【回答】

容易陷入"想过于聪明而创造不明确描述"的陷阱，**不明确会导致模型不清楚要用多少句子、什么风格**。通常**具体和直接更好**。反例："解释提示工程的概念。保持解释简短，只有几句话，不要过于描述。"——不清楚要多少句子和什么风格。更好的提示应非常具体、简洁、切中要点："**使用 2-3 句话向高中学生解释提示工程的概念**。"（明确了句数、受众与风格。）

## 【问题】

为什么应"说要做什么"而不是"不要做什么"？请举例。

## 【回答】

**避免说"不要做什么"，而应说"要做什么"**——说做什么更具体，并聚焦于有利于模型生成良好回复的细节。反例（电影推荐机器人）：

```
以下是向客户推荐电影的代理程序。不要询问兴趣。不要询问个人信息。
客户：请根据我的兴趣推荐电影。
代理：
```

输出失败：`当然，我可以根据你的兴趣推荐电影。你想看什么类型的电影？你喜欢动作片、喜剧片、爱情片还是其他类型的电影？`（模型仍在问兴趣。）

更好的提示：

```
以下是向客户推荐电影的代理程序。代理负责从全球热门电影中推荐电影。它应该避免询问用户的偏好并避免询问个人信息。如果代理没有电影推荐，它应该回答"抱歉，今天找不到电影推荐。"。
顾客：请根据我的兴趣推荐一部电影。
客服：
```

输出：`抱歉，我没有关于你兴趣的任何信息。不过，这是目前全球热门的电影列表：[电影列表]。希望你能找到喜欢的电影！`

以上示例部分摘自 OpenAI 官方《Best practices for prompt engineering with OpenAI API》。
