# 大模型微调方法

> 来源：「项目前预备知识」大纲（图片）。原文只给出知识点清单，未给出答案，
> 以下回答为根据公开资料整理。LoRA、P-Tuning 细节可对照 `AI_LoRA 低秩适配原理.md`、
> `AI_P-Tuning 与 Prefix-Tuning 对比.md`。

## 【问题】

什么是大模型微调（Fine-tuning）？为什么要微调？

## 【回答】

**微调是在预训练基座模型的基础上，用特定领域/任务的数据继续训练，使模型适配该场景**。

**为什么需要微调**：

- **补齐领域知识**：通用模型在**垂直领域（医疗、法律、金融、内部业务）** 表现不足。
- **规范输出风格与格式**：让输出**稳定符合业务要求的语气、结构、JSON Schema** 等。
- **纠正行为**：减少**拒答、冗长、不符合安全规范**的输出。
- **相比 Prompt 的优势**：能力**固化进参数**，**不占用上下文窗口**，**推理更快更省 token**。

**微调 vs RAG 的取舍**：

| 维度 | 微调 | RAG |
| --- | --- | --- |
| 知识更新 | **需重新训练**，时效性差 | **改库即生效**，时效性好 |
| 改变的是 | **模型行为/风格/能力** | **模型可见的外部知识** |
| 幻觉 | 仍可能幻觉 | **可给出引用来源**，更易核查 |
| 成本 | 训练成本高 | 主要成本在**检索与知识库维护** |

**结论：知识用 RAG，行为用微调**，生产中常**两者结合**。

## 【问题】

常见的微调方法有哪些？各自原理与适用场景是什么？

## 【回答】

按**更新参数量**由多到少：

1. **全量微调（Full Fine-tuning）**
   - **更新全部参数**，效果上限最高。
   - 代价：**显存与算力开销极大**（需存优化器状态、梯度），大模型常需多卡并行；**易灾难性遗忘**。

2. **冻结部分层 / Freeze 微调**
   - **冻结底层（通用语义），只训练高层或特定模块**，性价比折中，缓解遗忘。

3. **LoRA（Low-Rank Adaptation）**
   - **冻结原权重**，在旁路插入**低秩分解矩阵（A·B）**，**只训练这两个小矩阵**。
   - 优势：**可训练参数极少、显存占用低、可插拔切换、推理时可合并回原权重、无额外延迟**。
   - 适用：**绝大多数资源受限场景下的首选**。

4. **QLoRA**
   - **基座模型量化到 4bit（如 NF4）+ LoRA 微调**，进一步**大幅降低显存**，单卡可微调大模型。

5. **Prefix-Tuning / P-Tuning / P-Tuning v2**
   - **不改动模型主体权重**，在输入层（或各层）加**可学习的软提示（Soft Prompt）向量**。
   - **P-Tuning v2** 在**各层都加连续提示**，效果更接近全量微调。
   - 适用：**参数预算极小、生成类/NLU 任务**。

6. **指令微调（SFT）与 RLHF / DPO**
   - 严格说是**对齐阶段**的方法，目标是**对齐人类偏好与指令遵循**，而非注入知识。

**选择建议**：**先试 Prompt / RAG；行为与格式问题用 LoRA/QLoRA 微调；数据与算力充足且追求极致效果时再考虑全量微调**。
