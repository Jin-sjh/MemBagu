# Agent风险与人在回路

## 【问题】

Agent 的最大风险是什么？怎么防控？

## 【回答】

最大风险是**复合错误与权限滥用**——单步小错在多步被放大，或工具被诱导执行高危操作。对策：

- **最小权限**（工具白名单、参数校验）；
- **强审计**（记录轨迹）；
- **人在回路（HITL）**；
- **预算与步数上限** + 输出审核。

一句话：**限步、限权、可观测、可回滚**。

## 【问题】

怎么做「人在回路」又不打断用户体验？如何防止 Prompt 注入？

## 【回答】

人在回路分级：

- **低风险**自动执行；
- **中风险**异步审批；
- **高风险**实时确认。

产品上用**预授权**（如仅本次会话可读某目录）、**可撤销**、**默认最小权限**。向非技术经理可用「能办事的实习生」类比：能力强但可能记错/被误导/误操作，所以要权限卡、审批、监控录像（日志）、重要操作双人复核。

防 Prompt 注入：**工具层鉴权与用户身份绑定**；结构化分隔用户内容与指令（不让模型把历史记忆误判为当前指令）；敏感操作二次确认；输出侧 DLP；核心是把秘密留在系统侧、不进模型上下文。
