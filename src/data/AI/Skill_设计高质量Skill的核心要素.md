# Skill 设计高质量 Skill 的核心要素

## 问题1：设计高质量 Skill 时，Skill 描述（Description）的精准性需要考虑哪些方面？

## 【问题】
设计高质量 Skill 时，Skill 描述（Description）的精准性需要考虑哪些方面？

## 【回答】
Skill 描述是最关键的部分，它决定 Claude 是否会在正确时机触发这个 skill。需要考虑以下方面：

1. **触发条件要具体**：列举明确的用户意图、关键词、文件类型
2. **反向排除**：用 "Do NOT use when..." 避免误触发
3. **覆盖同义表达**：用户可能用不同方式表达同一需求（如 "Word文档"、"docx"、"正式报告"）

## 问题2：SKILL.md 的内容结构应该包含哪些要素？

## 【问题】
SKILL.md 的内容结构应该包含哪些要素？

## 【回答】
SKILL.md 的内容结构应包含以下要素：

1. **环境约束**：可用的库、工具版本、路径规范（这是最容易踩坑的地方）
2. **分步骤的操作指南**：不假设 Claude 已知细节，把每个步骤写明
3. **输出路径规范**：文件放哪里、如何命名
4. **错误处理**：常见失败场景和解决方案

## 问题3：设计高质量 Skill 时，可验证的输出标准包括哪些内容？

## 【问题】
设计高质量 Skill 时，可验证的输出标准包括哪些内容？

## 【回答】
可验证的输出标准包括：

1. 明确定义"好的输出"长什么样
2. 提供正面示例（和负面示例）
3. 指定格式、风格、质量检查点

## 问题4：设计 Skill 时为什么要遵循单一职责原则？

## 【问题】
设计 Skill 时为什么要遵循单一职责原则？

## 【回答】
遵循单一职责原则的原因：

1. 一个 skill 解决一类问题，不要试图覆盖所有情况
2. 过于宽泛的 skill 会降低质量，过于细碎则维护成本高

## 问题5：设计 Skill 时如何与其他 Skills 进行边界划分？

## 【问题】
设计 Skill 时如何与其他 Skills 进行边界划分？

## 【回答】
与其他 Skills 进行边界划分的方法：

1. 在描述中明确与相邻 skill 的区别（如 `pdf` vs `pdf-reading`）
2. 避免描述重叠导致 Claude 不知道选哪个

## 问题6：设计 Skill 时如何进行实际测试与迭代？

## 【问题】
设计 Skill 时如何进行实际测试与迭代？

## 【回答】
实际测试与迭代的步骤：

1. 用真实用户 prompt 测试触发率
2. 检查误触发（不该用时用了）和漏触发（该用时没用）
3. 根据失败案例修订描述和内容

## 问题7：设计 Skill 的快速自检清单包含哪些问题？

## 【问题】
设计 Skill 的快速自检清单包含哪些问题？

## 【回答】
快速自检清单包含以下问题：

| 问题 | 说明 |
|------|------|
| Claude 能在 3 秒内判断是否使用这个 skill 吗？ | 描述是否清晰 |
| 如果完全按 SKILL.md 操作，输出会正确吗？ | 内容是否完整 |
| 有没有其他 skill 会和它抢同一个触发场景？ | 边界是否清晰 |
| 在陌生环境（不同库版本）下还能工作吗？ | 鲁棒性如何 |
