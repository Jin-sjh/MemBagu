# 提示词基本概念

## 【问题】

什么是提示词（Prompt）？一个提示词可以包含哪些信息？

## 【回答】

提示词（Prompt）是**传递给模型的信息**，可以包含**指令（instruction）或问题（question）**，也可以包含其他详细信息，如**上下文（context）、输入（input）或示例（examples）**等。可以通过这些元素更好地指导模型，从而获得更好的结果。一个最简单的例子：仅给模型不完整句子 `The sky is`，模型会自动续写为 `blue.`，但结果可能不符合预期；加入明确指令 `Complete the sentence: The sky is` 后，模型给出 `blue during the day and dark at night.`，结果明显更好。

## 【问题】

什么是提示工程（Prompt Engineering）？

## 【回答】

**设计有效的提示词以指导模型执行期望任务的方法被称为提示工程（Prompt Engineering）**。核心思想是：**结果的质量与提供给模型的信息数量和完善度有关**——通过补充指令、上下文、输入或示例等元素来更好地指导模型，从而获得更好的结果。例如同样面对 `The sky is`，明确要求"补全句子"后模型输出质量显著提升。

## 【问题】

提示词的标准格式有哪几种？

## 【回答】

标准提示词可以写成两种基本形式：

```
<问题>?
```

或

```
<指令>
```

也可以使用**问答（QA）格式**：

```
Q: <问题>?
A: 
```

对于较新的模型，零样本提问时可以省略 `Q:` 前缀，直接提问，例如 `What is prompt engineering?`。

## 【问题】

什么是零样本提示（Zero-shot Prompting）？与少样本提示（Few-shot Prompting）的区别是什么？

## 【回答】

- **零样本提示（Zero-shot Prompting）**：**直接提示模型给出回答，而不提供任何任务示例或示范**。例如直接问 `Q: What is prompt engineering?`（较新模型可省略 `Q:` 前缀）。
- **少样本提示（Few-shot Prompting）**：**提供若干示例（示范），让模型从中学习任务模式**，即"小样本提示可以赋能上下文学习能力"。

区别核心在于**是否提供示例**：零样本不提供任何示例，少样本提供多个示例让模型通过上下文学习掌握任务模式。少样本提示的通用格式：

```
<问题>?
<答案>

<问题>?
<答案>

<问题>?
```

问答格式版本则为 `Q: <问题>?` + `A: <答案>` 重复若干组，最后以 `Q: <问题>?\nA:` 结尾。

## 【问题】

什么是上下文学习（In-context Learning）？与少样本提示的关系是什么？

## 【回答】

**上下文学习（In-context Learning）指语言模型基于提示中给出的示例或说明来理解并执行任务的能力**。语言模型可以基于一些说明了解和学习某些任务，而**少样本提示（Few-shot Prompting）正是赋能上下文学习能力的手段**。典型示例——情感分类，通过 4 条带情感标签的影评示例让模型学会分类：

```
This is awesome! // Positive
This is bad! // Negative
Wow that movie was rad! // Positive
What a horrible show! //
```

输出：`Negative`

## 【问题】

聊天模型（如 gpt-4 / gpt-3.5-turbo）的 system / user / assistant 三种角色分别是什么？

## 【回答】

使用 `gpt-4` 或 `gpt-3.5-turbo` 等**聊天模型**时，提示词可分为三种角色：

- **`system`**：**设定 assistant 的整体行为**，非必需但有用。
- **`user`**：**用户输入**，可直接作为 prompt。
- **`assistant`**：**模型响应**，也可以**手动定义来提供示例**。

为简化，Prompt Engineering Guide 后续示例默认**只使用 `user` 消息作为 prompt**。
