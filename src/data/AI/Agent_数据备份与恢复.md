# 数据备份与恢复

## 【问题】
对话历史、向量索引、用户配置等关键数据怎么防丢失、怎么恢复？

## 【回答】
按数据分级定 RPO/RTO（以下为该文档工程实践口径）：
- **数据分级**：核心数据（知识库原文、用户配置）RPO=0 实时同步备份；重要数据（对话、向量索引）RPO<1h 每小时增量；可重建数据（缓存、报表）每日备。
- **备份策略**：PostgreSQL 流式复制+每日全量+WAL 归档；Milvus 定期 snapshot（原始文档可重建索引）；Redis RDB 每小时 + AOF。
- **恢复演练**：每季度灾演（主库故障/向量损坏/Redis 清空），记 RTO 是否满足 SLA。
- 要点：**向量索引丢了可从原始文档重算 embedding，所以备份重心在原始文档与配置**；**恢复能力要靠演练验证，不能只写不练**。
