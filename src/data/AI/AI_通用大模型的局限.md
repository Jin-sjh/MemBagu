# 通用大模型的局限

> 来源：「项目前预备知识」大纲（图片）。原文只给出知识点清单，未给出答案，
> 以下回答为根据公开资料整理。RAG 部分可对照 `大模型_检索增强生成.md`、
> `大模型_RAG减少幻觉.md`。

## 【问题】

通用大模型存在哪些问题？为什么企业落地往往不能直接用它？

## 【回答】

**1. 幻觉（Hallucination）**

- 模型会**自信地生成看似合理但错误的内容**，本质是**基于概率的续写而非事实检索**。
- 在高风险场景（医疗、法务、金融）**不可直接采信**，需要**引用溯源 + 人工复核**。

**2. 知识时效性与更新成本**

- 参数中的知识**截止于训练数据时间**，无法自动获取最新信息。
- 更新知识需要**重新训练/微调**，**成本高、周期长**，且**可能引发灾难性遗忘**。

**3. 缺乏私有领域知识**

- 通用语料中**不存在企业内部文档、业务规则、客户数据**，无法回答私有问题。
- 直接把私有数据喂给公有云 API 还存在**数据合规与泄密风险**。

**4. 上下文窗口有限**

- 长文档**无法一次性塞入**；长上下文还有 **Lost in the Middle（中部信息易被忽略）** 问题。

**5. 能力与行为问题**

- **复杂推理不稳定**、**数学与计数能力弱**；**指令遵循与输出格式不稳定**（JSON 易出错）。
- **偏见与安全风险**、**提示词注入**、**无法可靠执行外部动作**。

**6. 成本与延迟**

- 大模型推理**算力成本高**、**首 token 延迟大**，高并发下成本敏感。

**7. 可解释性差**

- 难以解释**为什么给出该答案**，**责任归属与审计困难**。

## 【问题】

针对这些局限，业界常用的解决思路是什么？

## 【回答】

| 局限 | 主要解法 |
| --- | --- |
| 幻觉 | **RAG 提供事实依据 + 引用来源**、**降低 temperature**、**事实验证/自检链路** |
| 知识时效 | **RAG 外挂实时知识库**、**增量微调** |
| 私有知识 | **私有化部署 + RAG 企业知识库**、**数据脱敏** |
| 上下文受限 | **文档切分（Chunking）+ 检索**、**长上下文模型**、**摘要压缩** |
| 输出不稳定 | **Few-shot 示例、结构化输出约束、函数调用（Function Call）** |
| 成本高 | **小模型/量化/蒸馏、缓存、路由分流** |
| 无法执行动作 | **Agent + 工具调用**、**工作流编排** |

**核心结论**：**通用大模型的短板和「知识外置 + 能力编排」直接相关，这正是 RAG、Agent、LangChain 这类技术存在的理由。**
