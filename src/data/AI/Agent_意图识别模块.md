# 意图识别模块

## 【问题】
RAG/Agent 客服场景里，意图识别模块一般怎么实现？怎么处理多意图和隐含意图？

## 【回答】
推荐**两阶段意图识别**（以下为该文档工程实践口径，阈值需按你的评估集调）：
- **第一阶段粗分类（低延迟、覆盖大部分流量）**：规则（正则匹配订单号等高频模式）+ 轻量分类器（如 FastText），延迟 < 5ms，**快速响应约 80% 常见查询**。
- **第二阶段精分类（LLM）**：对粗分不确定的复杂查询，用结构化 Prompt 输出标准 JSON（含 intent 类型、confidence、entities），**支持多意图识别与实体抽取**。
- **三级意图体系**：L1 咨询/操作/投诉/闲聊 → L2 产品/技术/订单/退款 → L3 具体产品线/操作类型，**层级化便于路由与统计**。
- **置信度阈值策略**：confidence ≥ 0.85 直接执行；0.6–0.85 向用户确认；< 0.6 追问澄清。
- 收益：**第一阶段拦掉大部分流量，LLM 调用量显著下降，省 token**；关键工程点是**把简单模式用规则/小模型兜住，LLM 只处理真正需要语义判断的 query**。
