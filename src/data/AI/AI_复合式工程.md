# 复合式工程

## 【问题】
什么是「复合式工程（Compound Engineering）」？它和传统开发模式有什么本质区别？

## 【回答】
复合式工程源自编程中的「复利」隐喻，追求的是一种**「复利」效应：让系统的能力随着时间推移指数级增长**，而不是随功能增加变得越来越难维护。它的核心目标非常明确：**让每一单元的工程工作使后续工作变得更容易，而非更难。**

与传统开发的对比：

| 传统开发 | 复合式工程 |
|---------|-----------|
| 累积技术债务 | 每个功能产出文档模式 |
| 每个功能增加复杂性 | 创建可复用组件 |
| 代码库越来越难维护 | 建立减少决策疲劳的约定 |
| 知识不增长 | **知识在团队中复合增长** |

一句话概括：**传统工具帮你「做事」，复合工程帮你「越做越快」**——做同类事情的成本随次数递减，而不是边际成本恒定。

## 【问题】
复合式工程的工作流循环是什么？知识复利如何在其中发生？

## 【回答】
核心工作流循环：**Plan → Work → Review → Compound**，其中 Compound 的意义是**知识复合：下次规划更精准**。

复利落地的典型过程（以「brief 生成中的 N+1 query 问题」为例）：

- 第一次解决：Research（约 30 分钟）→ 文档化到 `docs/solutions/performance-issues/n-plus-one-briefs.md`（约 5 分钟）；
- 下次遇到类似问题：Quick lookup（约 2 分钟）→ 知识复合 → **Team gets smarter**。

量化效果（同类需求的时间成本，如「商品发放」类需求）：

| 模式 | 第1次 | 第2次 | 第3次 | 第N次 |
|------|-------|-------|-------|-------|
| 传统（speckit 模式） | 45分钟 | 45分钟 | 45分钟 | **45分钟（边际成本恒定）** |
| AI 工程化模式 | 45分钟 | 15分钟 | 10分钟 | **5分钟（边际成本递减）** |

核心差异：**知识位置不同**——传统工具的知识在人脑（每次重新想），AI 工程化的知识在 `context/` + `skill/`（沉淀复用）。**知识流向**：传统是「人脑 → Spec 文档 → 代码（下次还要从人脑开始）」；AI 工程化是「人脑 → context/ → Skill → Command（**知识留在工具链里，下次直接复用**）」。

## 【问题】
Anthropic / Claude Code 团队如何实践复合式工程？有哪些可复制的案例？

## 【回答】
Anthropic 工程团队的实践印证了复合式工程的四个特征：

1. **错误转化为系统的免疫能力**：PR 犯错时，团队会说「把这个加到 CLAUDE.md 里，下次就不会再犯了」——不只修一次，而是把教训编码进系统。
2. **AI 深度参与工程资产生产**：Claude Code 内部**几乎 100% 的测试是 Claude 写的，Lint 规则也 100% 是 Claude 写的**。
3. **知识沉淀让人人可上手**：十年未写代码的经理 Fiona 加入第一天就开始提交 PR——因为 Claude Code 里积累了所有团队的实践经验，**系统「记得」怎么写代码**。
4. **记忆内置而非外部依赖**：把实现功能的过程记录并编码回 prompts、sub-agents、slash commands。

## 【问题】
「极简主义」与「工具隐形化」和复合式工程有什么关系？

## 【回答】
极简主义是复合式工程的设计哲学，要点：

- **最好的工具，就是没有工具**；**减少模型的选择，就是增加模型的能力**。
- **模型吞噬脚手架**：曾经需要外部辅助的部分，逐渐被模型自身吸收。
- 设计影响：入口极简化（整个系统只有 `/req-dev`、`/optimize-flow` 两个命令入口）；把能力编码为 Skill 让 Agent 自动调用；**上下文自动加载**（用户感受不到「加载」动作，但 AI 已具备完整信息）；**删除优先于添加**（每次迭代问「有哪些东西可以删掉」）；**双重用户设计**（同一能力可被人和 Agent 调用）。
- **让工具尽可能「隐形」**：用户只需要说「我要做一个商品发放需求」，系统自动加载上下文、自动识别阶段、自动调用 Skill、自动沉淀经验——用户在「完成工作」而不是「使用工具」。

引申判断（黄仁勋）：**AI 改变的是「任务」，而非「职业」**——被接管的是信息检索、样板代码、格式化、重复配置，人依然主导系统设计、架构决策、质量判断、创新突破。
