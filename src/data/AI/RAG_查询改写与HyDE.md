# 查询改写与HyDE

## 【问题】
什么是查询改写（Query Rewriting）？会不会引入噪声？

## 【回答】
查询改写把用户原始口语问句改写成**更易被检索匹配**的形式，或生成**多条查询变体**做多路召回（口语"咋办" vs 文档"处理流程"，改写可对术语对齐）。
- 策略：同义扩展、拆问句、补全主语；或用 LLM 生成检索友好的 query 变体多条再融合。
- **会引入噪声**：LLM 可能**篡改实体**或**添加未提及条件**。对策：多路检索 + RRF、重排、引用校验；高敏场景用**人工词表 + 模板**优先。
- 实践中**需要保留原 Query**，常"原句 + 改写句"同时检索再融合，避免改写跑偏。

## 【问题】
什么是 HyDE（假设文档嵌入）？适合什么、不适合什么？有什么风险？

## 【回答】
HyDE 让 LLM 先写一段**假想的答案文档**（可能含错），再对假想文档做 embedding 去检索，拉近查询与文档在向量空间的距离，缓解**查询与文档表述风格不一致**。
- **适合**：表述差距大、短查询难对齐长文档。
- **不适合**：强事实约束且模型易胡编的领域，除非加强校验与拒答。
- **风险**：假想文档可能引入错误主题，需**重排与引用校验**缓解。

## 【问题】
Step-back Prompting 和 HyDE 有什么异同？

## 【回答】
二者都试图**拉近查询与文档的语义距离**：
- HyDE 用**假想答案文档**做 embedding，**更激进**（易引入虚构事实）。
- Step-back 先生成**更抽象的后退一步问题**（背景原理），再并行检索"具体问题 + 抽象问题"，**相对克制**（仍停留在问题空间）。
实践可并行检索后由重排裁决。

## 【问题】
什么是子问题分解？典型失败模式是什么？和 Agent 多步检索有什么区别？

## 【回答】
对**多跳、多条件**问题，先拆成子问题序列，每个子问题单独检索，再拼接或图式合并证据；单句 embedding 难覆盖"先 A 再 B"的复合语义，分解后每步更聚焦。
- **失败模式**：分解错误（实体指代错）、子问题遗漏约束、合并时矛盾未检测；需要**一致性检查与重排**过滤无关块。
- **与 Agent 区别**：子问题分解可以是固定模板/一次 LLM 调用；Agentic 更强调**动态决定是否再检索**，工具边界更宽。
