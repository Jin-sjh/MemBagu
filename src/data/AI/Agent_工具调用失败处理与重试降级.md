# 工具调用失败处理与重试降级

## 【问题】
Agent 调用外部工具 / 多 Agent 通信失败时，怎么保证系统的鲁棒性？

## 【回答】
分层错误处理 + Agent 自愈 + 消息持久化（以下为该文档工程实践口径）：
- **错误分类处理**：临时错误（超时/限流）重试最多 2 次；参数错误把错误回给 Agent 让其修正；权限/数据不存在直接告知用户；系统错误降级。
- **Agent 自愈**：工具失败信息作为 Observation 返回，**由 LLM 决定改参数重试 / 换替代工具 / 告知用户**；连续失败 3 次则跳过该工具，退化为纯 RAG 回答。
- **多 Agent 通信**：每跳设超时（30–60s），健康检查连续失败标记不可用，任务重分配给备份 Agent；**Agent 间消息用 Redis Stream 持久化，消费方重启不丢消息**。
- **断点续传**：复杂任务中间状态持久化到 Redis，崩溃后从最近检查点恢复，省 token。
- 要点：**可重试的才重试，能降级的降级，不能恢复的明确报错；自愈决策交给 LLM 而非硬编码**。
