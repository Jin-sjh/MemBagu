# 技能安全防护

## 【问题】
技能的安全防护要防哪两类风险？

## 【回答】
- **「防坏人」**：来自第三方的**恶意技能**，有可能做出和其内容描述完全不一样的事情，比如滥用执行权限窃取你的敏感信息，甚至悄悄破坏你的系统文件。
- **「防自己」**：你自己刚写好的新技能可能存在**逻辑漏洞**，一不小心删错了重要文件。

## 【问题】
技能安全的「三道闸」是什么？

## 【回答】
- **第一道闸：最小权限（发门禁卡）**——只给智能体完成当前任务所需的**最小权限**。如果只需要读取文件，就不要给写入权限；如果只需要访问某个文件夹，就不给整个硬盘的访问权限。
- **第二道闸：二次确认（按暂停键）**——遇到高风险操作一定要设置二次确认。高风险操作指**删除文件、发送邮件、执行未知代码、访问敏感数据**这类一旦执行就很难撤销的动作。好的技能会在这些关键节点暂停，等你确认后再继续（如 Claude Code 弹出的执行确认框）。
- **第三道闸：可追溯（装摄像头）**——确保智能体的**所有操作都有记录**：查看了哪些数据、修改了哪些文件、调用了哪些工具。配合 Git 这类版本管理工具，还能随时回退到文件修改之前的状态，把损失降到最低。

## 【问题】
日常使用技能要养成哪四个安全好习惯？

## 【回答】
- **习惯一：安装前，先「安检」（针对别人的技能，防「投毒」）**——先让智能体帮你当保安：「帮我检查这个技能的 SKILL.md 和 scripts/ 目录。」重点检查 5 项：
  1. SKILL.md 是否写清楚：从哪里读、写到哪里、会不会联网、是否拉取外部 URL？
  2. 脚本里有没有隐藏的删除、覆盖、上传、外联等高风险动作？
  3. 生成的文件会不会直接覆盖你的原文件？
  4. 是否以任何借口要求你填写密码、密钥等敏感信息？
  5. 如果安装库等软件，核对名字拼写（当心骗子把库名拼错一个字母来伪装恶意包，尤其是热门库）。

  **注意：从外部 URL 获取数据的技能风险非常高**，即使技能本身可信，它拉取的外部内容也可能包含恶意指令。
- **习惯二：第一次跑，用假数据（防翻车）**——不论别人的技能还是自己刚写的新技能，第一次都**绝对不要拿公司真数据或重要文件去测**，因为新手写的脚本极容易出现「覆盖原文件」「全选删除」等逻辑失误。先用假数据测试文件跑一遍，确认生成的文件存对了地方、没破坏原稿，再上真实数据。
- **习惯三：日常干活，建个专属文件夹（防越权）**——永远在专门新建的文件夹里使用智能体，不要在桌面、系统根目录（如 C 盘）直接让它执行操作。
- **习惯四：看清弹窗，绝不「无脑点『是』」（防误操作）**——二次确认框弹出时强迫自己停下来，先看清要执行的命令到底是什么，确认没有高风险动作后再点「允许」。

## 【问题】
个人自用的技能，投入使用前要过哪些安全检查项？

## 【回答】
**权限控制**
- 读取哪些目录，是否超出业务必需的范围；
- 写入哪些目录，是否限定在 `output/` 等安全路径；
- 是否需要联网，仅访问可信域名；
- 按需启用代码执行，明确执行边界和用途。

**不可逆操作保护**
- 删除操作前确保二次确认；
- 发布操作前增加预览校验；
- 覆盖文件前检查同名文件，遇到同名文件先备份。

另外可按**风险等级**把技能分为低风险、中风险、高风险三类，采取不同级别的安全措施。
