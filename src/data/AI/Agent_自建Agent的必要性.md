# 自建Agent的必要性

## 【问题】
通用 Agent（如豆包、扣子、Codex）+ MCP 已经能连上公司系统、拿到内部数据、调 API 完成大部分任务，企业为什么还要自己开发 Agent？

## 【回答】
核心结论——**接通 ≠ 懂业务**。MCP 解决的是"管道问题"（数据能从 A 流到 B），但没解决"决定问题"（流过来的数据意味着什么、下一步该做什么）。打个比方：MCP 就像给一个外实习生发了门禁卡，他能进公司、看到系统了，但他不知道报销超过 5000 要走部门经理审批、不知道差旅费要核对行程单、不知道同一张发票可能已被提交过。

技术上通用 Agent + MCP 确实能"提交一张报销单据"，但真实需求远不止提交：发票有没有重复提交过？5000 块要不要走二级审批？这个月差旅预算还剩多少？被驳回了怎么告知原因？这些事通用 Agent + MCP **不是技术上行不通，而是不可靠**。真正需要的是"懂业务"，而这恰恰是通用 Agent 缺少的企业上下文。

## 【问题】
把业务规则写进 MCP 的工具描述（prompt），告诉 LLM 先查重 API、再查预算 API、超预算就预警，让它按步骤执行不就行了吗？为什么 LLM 扛不了业务的确定性要求？

## 【回答】
因为 **LLM 是概率模型，不是确定性程序**。对于简单流程，把规则写进工具描述确实能跑；但问题出在 LLM 的本质上：

- 处理 10000 笔报销，99% 遵守流程 = **100 笔出问题**，可能是跳过了查重、顺序搞反了、把"如果"的条件理解反了。
- 最致命的是**没法复现**：同样的输入，LLM 这次走对了，下次可能走错。它不是故意不听话，而是概率模型天生没有"必须"这个概念。

对企业来说，**"大概率对"在业务场景里等于"不可接受"**。能写进工具描述的简单流程只是少数，复杂业务无法靠 prompt 把确定性"写进去"。

## 【问题】
Workflow、Agent、通用 Agent 三者有什么区别？企业应该怎么选？

## 【回答】
三者的本质区别在"谁来决定下一步"：

- **Workflow**：代码写死流程，先 A 再 B 再 C，没有岔路。适合规则明确的场景——报销审批路由、合同到期提醒。
- **Agent**：LLM 自主决策，观察当前状态 → 决定下一步干什么 → 执行 → 再观察。适合**无法预先写死所有路径**的场景——欺诈调查、复杂客诉处理。
- **通用 Agent**：有自主决策能力，但缺少你的企业上下文。

关键判断：企业很多流程根本不需要 Agent——报销审批大概率用 **workflow** 就够了。真正需要 Agent 的是那些"每一笔情况都不一样"的场景。**先问"这个场景需要 LLM 自主决策吗？"，而不是"要不要自建 Agent"。**

## 【问题】
开源 Agent 框架（Hermes、LangGraph、CrewAI 等）拿过来"稍加改造"——固定上下文、加几个 tool 函数、屏蔽不需要的功能——不就完事了？为什么还要专门养 Agent 开发团队？

## 【回答】
所谓"稍加改造"听起来像三行代码，实际上每一项都是独立工程，需要设计、测试、调优，这**才是 Agent 开发的真实工作量**：

- **上下文工程**：写 system prompt（Agent 的角色、规则、行为边界）、设计 few-shot examples（教 Agent 在你的业务里怎么判断）、管理上下文窗口（对话长了哪些信息保留、哪些丢弃、什么时候压缩）。不是写一段话，而是需要反复试错，周期以周计。
- **工具工程**：每个工具的描述怎么写 LLM 才能正确调用？参数边界怎么设才不会互相冲突？两个工具功能类似时怎么让 LLM 选对？工具返回的格式怎么设计 LLM 才好理解？这直接决定 Agent 的**决策准确率**。
- **Guardrail 工程**：什么操作不允许？什么场景需要人类确认？误拦了怎么办？直接影响**业务安全**。

开源框架给你的是**毛坯房，装修才是大活**。

## 【问题】
既然底层机制（ReAct 循环、上下文管理、工具调度）和通用 Agent 区别不大，自建 Agent 的价值到底在哪？

## 【回答】
价值不在"造引擎"，而在"调引擎"。类比 2015 年的 Web 开发：没人再从零写框架，但 Web 开发者需求反而暴增——因为要做的东西多了。Agent 也一样：

- **引擎层**：ReAct 循环、工具调度、上下文管理——开源框架已经解决了，不需要自己造。
- **定制层**：上下文设计、工具工程、边界安全、测试评估——每家企业必须自己做，因为**每家的业务上下文都不一样**。

核心推论：**通用 Agent 越强，企业用 AI 的门槛越低；门槛越低，用 AI 的企业越多；企业越多，需要定制上下文、设计工具、设定边界的需求就越大。** 这不是"市场缩不缩小"，而是"市场从造引擎转向调引擎"。通用 Agent + MCP 让你能"连得上"，但要让 Agent 真正"干得对"——理解你的业务、接入你的系统、守好你的边界——这部分工作**不会因为通用 Agent 变强而消失，反而会因用 AI 的企业变多而增长**。引擎是标准件，调校是手艺活，而手艺活别人替不了你。

## 【口诀】
接通≠懂业务，概率扛不住确定；引擎不用自己造，调校（上下文/工具/护栏）才是真手艺。
