# 系统容量规划与并发评估

## 【问题】
上线前怎么评估系统能扛多少并发？容量又该怎么规划？

## 【回答】
用压测找容量上限 + 容量模型做规划（以下为该文档工程实践口径）：
- **压测方法**：用 Locust 分布式压测，按比例混合简单问答/RAG/多轮/工具调用；记录不同并发下的 P99 延迟、QPS、错误率。
- **找瓶颈**：常见瓶颈在 **LLM API 的 QPS 限制与延迟**，向量库在高位并发下仍轻松；可借模型路由缓解。
- **定安全容量**：如 P99<5s、错误率<0.5% 对应 150 并发，日常高峰留余量。
- **容量模型**：所需 Pod 数 ≈ 峰值 QPS / (单 Pod QPS × 0.7 安全系数)；向量库 1000 万向量约 48GB 内存；按历史线性回归预测 3–6 月增长、季度评审。
- 要点：**容量规划 = 压测测出的上限 × 安全系数，并随增长季度复核**；弹性扩缩容在超过阈值（如 120 并发）时自动扩 Pod。
