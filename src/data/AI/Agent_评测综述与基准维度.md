# 评测综述与基准维度

## 【问题】
为什么说评估 LLM-based Agent 需要全新的范式（paradigm），而不能沿用静态大模型的评估方式？

## 【回答】
静态 LLM 知识固定、仅做**文本到文本的交互**；而 Agent 以 LLM 为 backbone，被集成进**多步工作流**并装备**外部工具**，能够自主规划、执行、并**在真实环境中适应**复杂策略。

因此评估不能只衡量 LLM 的**文本输出质量**，而必须评估 agent **在动态环境中，通过一系列动作与交互完成用户任务**的能力（即 sequential decision-making / 序列化决策）。此外，论文强调评估基准必须**随 agent 能力共同演化**，持续容纳新的任务类别与领域。

## 【问题】
这篇关于 LLM-based Agent 评估的综述，把整个评估领域从哪五个视角展开？

## 【回答】
论文沿五个视角组织：

- **(1) 核心 LLM 能力评估**：规划、工具使用、自我反思、记忆等 agent 工作流所需的基础能力。
- **(2) 应用特定基准**：Web Agent、软件工程 Agent 等具体应用场景。
- **(3) 通用 Agent（generalist）评估**：需要综合能力、跨应用的 agent。
- **(4) 基准核心维度分析**：从数据策展、环境、接口、指标、安全等正交维度横向比较各类基准。
- **(5) 面向开发者的评估框架与工具**：集成进开发周期、支撑全流程评估的框架。

## 【问题】
Agent 评估基准的核心维度（core benchmark dimensions）有哪五个？

## 【回答】
论文沿五个**正交（orthogonal）维度**横向分析基准：**数据策展（Data Curation）**、**环境（Environment）**、**接口（Interface）**、**指标（Metric）**、**安全（Safety）**。这一视角能揭示基准之间的共同结构模式与现存缺口。

## 【问题】
评估环境分静态与动态，两者区别是什么？为什么动态环境更重要？

## 【回答】
**静态环境**（如原始 Mind2Web）依赖离线轨迹或缓存网页，agent 预测下一步动作但**不影响环境状态**。它可扩展，但**无法捕捉错误的级联效应**——错误动作没有下游后果，从而漏掉会导致任务失败的复合失败（compounding failures）。

**动态环境**（如 SWE 用的 Docker 容器、Web 用的浏览器沙箱）允许 agent 与活/模拟世界交互，其**动作会改变它随后观察到的状态**，从而能在长程任务中诊断失败模式。论文指出：随着 agent 能力增强，基准必须拥抱**动态环境**以评估长程交互能力。

## 【问题】
Agent 与环境的接口（interaction interface）分哪三类？

## 【回答】
- **代码与终端接口（Code & Terminal）**：要求 agent 生成可执行脚本（Python / Bash / SQL），主导 SWE 与科学类基准，成败取决于逻辑与语法正确性。
- **工具接口（Tools）**：动作被限制为预定义函数调用，靠 schema 遵从（schema adherence）达成目标，代表如 τ-Bench、AppWorld。
- **图形用户界面（GUI）**：通过可访问性树（HTML DOM）或视觉 UI 模拟人类交互，Web 与消费类应用基准用它评估视觉定位与网页/计算机导航。

## 【问题】
Agent 评估的指标（metric）有哪些类型？为什么仅有二元完成指标不够？

## 【回答】
最普遍的是**任务完成（task completion）**，但实现因应用而异：

- SWE 类（输出是功能代码）采用**基于执行的单元测试**（execution-based unit testing）。
- 需要修改环境状态的任务（如 τ-Bench）采用**状态匹配（state matching）**，将修改结果与 gold state 对比。
- 多步推理任务（如 GAIA）采用**答案匹配（answer matching）**，将简短确定答案与 gold 标准比对。

论文指出：这种**二元结果指标不足以理解 agent 的中间进度**，呼唤更细粒度的评估方案。

## 【问题】
安全与鲁棒性维度在现有基准中处于什么状态？

## 【回答】
多数基准优先考察**能力**；而**安全（safety）与鲁棒性（robustness）对企业落地至关重要，却很少被测试**。

- 鲁棒性常用 **pass^k** 衡量——即 agent 在 **k 次独立运行全部成功**的任务占比。
- 企业 agent 还需遵守数据隐私、访问控制等严格策略，但标准基准很少覆盖。
- 论文建议未来基准应集成 "guardrail" 指标，**对通过不合规动作达成任务成功**的 agent 进行扣分（例如删除了生产数据库却完成任务）。
