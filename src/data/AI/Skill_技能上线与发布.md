# 技能上线与发布

## 【问题】
上线发布前，动作取决于什么？三种场景的要求如何叠加？

## 【回答】
取决于**你想给谁用**，三种场景要求逐级叠加、门槛越来越高：

- **给自己用**：过一遍安全清单就行（见本项目 `Skill_技能安全防护.md`）；
- **给团队用**：还要考虑**分发**和**质量**；
- **给社区用**：在做好前面工作的基础上，还要考虑**配套文档、环境兼容性和长期可维护性**。

## 【问题】
在团队里推广技能，要提前想好哪两件事？

## 【回答】
1. **怎么分发**。简单做法是把技能提交到团队项目的代码仓库里（比如放在项目仓库的 `.claude/skills` 目录下），团队成员自动获取；规模更大的团队可以搭建**内部技能市场**，由成员自主选择安装哪些技能，**避免将所有技能全部塞进每个人的上下文**（上下文空间有限）。
2. **怎么保证质量**。技能创建门槛很低，容易出现**质量参差或功能重复**的问题。Anthropic 内部的做法是**先在沙盒文件夹里试用或在 Slack 中推荐给同事，获得足够关注后再正式发布到技能市场**。一般不需要专门的审核委员会，但需要某种机制确保「**发布前有人用过，觉得好用**」。

## 【问题】
发布到社区前要做哪些自查？

## 【回答】
用户决定要不要安装一个技能，整个过程可能不超过一分钟，关注的无非三点：**简介能不能看懂、有没有示例判断效果、装完能不能跑通**。发布前清单：

1. **重新审视 description**：面向陌生人，一句话说清干什么，覆盖常见触发说法。
2. **说明文档（README 或技能简介）**：功能说明 + **使用示例** + 依赖说明 + 兼容性。其中**使用示例最容易被忽略、也最有用**——用户不想读三段话理解你的技能，他想看一眼「输入什么、输出什么」再做决定。
3. **清理个人信息**：搜索 `key`、`token`、`password`、绝对路径，确认无残留。
4. **加版本号**：frontmatter 里加 `version` 字段，初始版本可标注为 `v1.0.0`。

**私密信息处理**：如果技能依赖 API Key 或特定的本地路径，不仅要删掉你的私密信息，还要在 SKILL.md 中用 `<YOUR_API_KEY>` 这样的占位符代替，并在 README 的醒目位置提醒用户配置自己的环境变量。

一句话：**含私密密钥、专属接口、敏感本地路径的技能，不要上架公开社区。**
