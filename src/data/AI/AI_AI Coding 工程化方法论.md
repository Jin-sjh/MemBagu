# AI Coding 工程化方法论

## 【问题】

为什么 AI 直接写代码容易"翻车"？如何通过 SDD+TDD 让 AI 有章法地 Coding、产出高质量代码产物？

## 【回答】

不加约束时，AI 会自由发挥，实现过程**缺乏章法、进度与质量不可控、经验难以沉淀**，在架构升级、跨语言重构等大型项目上尤为突出。两个主流方案各有短板：

- **单独用 OpenSpec/AmsSpec（SDD 管"写什么"）**：需求管得很清楚——proposal、design、specs、tasks 一条龙生成；但执行阶段 apply 只是逐个勾选 task，**没有 TDD 强制、没有子代理隔离、也没有自动审查**，AI 一步就能完成整个功能。结果是代码一次生成、过程无法插手，编译不过、单测不过、规范不过时要花大量时间调试。
- **单独用 Superpowers（TDD 管"做什么"）**：RED-GREEN-REFACTOR 强制循环、子代理隔离、两阶段自动审查，纪律很严；但**没有 spec 管理、没有变更追溯**，需求全靠对话，换个会话就忘了，无法形成标准体系。

两者结合（一站式平台 OpenSpec+Superpowers 强强联合）形成"核动力驱动"：**方案 → Plan → Stub → TDD → 覆盖率 → 验证**的七阶段流程，配合强制审查节点。依托一站式平台**断点续传、文档持久化**能力，做到：不依赖连续会话（新会话可断点续传、增量接力）、不依赖研发经验（技术方案确定后任何人接手质量几乎一致）、不依赖文字功底（遇事不决直接问 AI 下一步）、可发布（每小步完成即可提交空跑供复用）。

**面试要点**：核心不是"让 AI 随便写"，而是用 SDD 约束"写什么"、TDD 约束"怎么做"，把个人经验沉淀为可复用、可治理的组织级研发能力。

## 【问题】

一站式平台把 AI 编码流程切成哪几个阶段？有哪些核心机制保证质量？

## 【回答】

整体为 **7 大阶段（Phase 0~6）**：技术方案（Phase 0）→ 实施规划（Phase 1）→ Stub 生成（Phase 2）→ TDD 执行（Phase 3+4）→ 覆盖率（Phase 5）→ 验证+MR（Phase 6）→ 发布。7 大核心要素：

1. **主流程可回退**：每个 Phase 后设用户确认菱形决策，不通过沿红色虚线回退重做当前 Phase。
2. **多模块联动**：Phase 3+4 横向并行 5 条泳道——Proto/Stub、业务层、存储层、配置、测试。
3. **用户确认闭环**：每步都有"用户确认？"节点，**不确认绝不前进、不猜测、不自行决策**。
4. **Phase 3+4 多轮循环**：TDD 微循环（Red → Green → Refactor → Document）+ 符合预期决策，不符则紫色虚线回环直到通过。
5. **每步调整同步更新方案**：保证"代码与 iWiki 文档永不脱节"。
6. **双轨交付**：需求完成后同时产出代码（MR）+ 文档包（含 readme/plan/design/progress/review 五目录）。
7. **变更摘要为核心产物**：以 ★变更摘要★ 为金色突出，作为 MR 评审、上线通告、发布复盘的第一参考材料。

**关键价值**：强制审查节点把"AI 一次跑完所有代码"变成"AI 完成一个阶段 → 人审 → 放行 → 进入下一阶段"，让错误在**最便宜的时候被发现**。
