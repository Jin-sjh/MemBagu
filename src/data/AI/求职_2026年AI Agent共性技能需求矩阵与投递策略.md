# 2026年AI Agent共性技能需求矩阵与投递策略

## 【问题】
问：从共性技能矩阵看，AI Agent 岗位对编程语言和框架的要求分布是怎样的？

## 【回答】
基于文档第 2 节岗位归纳的编程语言要求分布：

| 语言 | 出现情况 | 典型用途 |
| --- | --- | --- |
| Python | 高 | LLM 应用、Agent 编排、脚本与评测、多数开源框架首选 |
| Go | 高（腾讯、字节后端常见） | 高并发服务、平台侧、与现有微服务栈一致 |
| Java | 中–高（腾讯等） | 企业级后台、与存量系统互通 |
| C++ | 中 | 性能敏感模块、部分基础设施或客户端相关后端 |

框架要求分布：

- **LangChain**：高，入门与原型常见。
- **LangGraph**：高，字节剪映等强调图编排与状态。
- **AutoGen**：中–高，多 Agent 对话与角色分工。
- **自研编排 / 状态机**：中，大厂线上常部分自研。

结论：**Python 是 LLM/Agent 首选语言，Go 在高并发后端高频，Java 偏企业集成，框架层 LangChain/LangGraph 几乎成标配**。

## 【问题】
问：核心技术点（LLM、RAG、Agent、Tool Calling 等）在腾讯、小红书、字节的面试权重矩阵是怎样的？

## 【回答】

| 技术点 | 腾讯 | 小红书 | 字节（剪映） | 综合 |
| --- | --- | --- | --- | --- |
| LLM 基础与 Prompt | ●●● | ●●● | ●●● | 全员必备 |
| RAG | ●●● | ●●（加分） | ●● | 极高 |
| Agent / Planning | ●●● | ●●● | ●●● | 极高 |
| Tool Calling | ●●● | ●●● | ●●● | 极高 |
| 记忆与上下文 | ●● | ●●● | ●●●（槽位设计） | 高 |
| 分布式系统 | ●●●（运维岗） | ●● | ●●● | 高 |

## 【问题】
问：针对 AI Agent 求职，文档把技能分成哪三类优先级？每类分别有哪些？

## 【回答】
文档依据岗位出现频次、面试追问深度与落地难度，把技能分为三层：

**必备技能（Must Have）**：
1. **Python 后端能力**：异步 IO、API 设计、依赖注入与模块化，能独立部署带工具调用的 Agent 服务。
2. **LLM 应用基础**：消息格式、流式输出、常见参数（temperature、max_tokens）、限流与重试。
3. **RAG 全流程**：切分、embedding、向量库、重排序、幻觉与引用溯源对策。
4. **Tool Calling**：JSON schema、函数描述、错误处理、并行与串行工具策略。
5. **Agent 范式**：ReAct / Plan-and-Execute 能口述+能画图，理解「何时结束」与「状态」。
6. **基础 Prompt Engineering**：角色、约束、Few-shot、输出格式（JSON/XML）。
7. **Git 与工程习惯**：可审查的仓库结构、最小可运行示例、README 与复现步骤。

**加分技能（Nice to Have）**：LangGraph（或同类）、公有云（AWS/GCP/Azure 任一）、K8s/Docker、对齐与微调入门（SFT 数据格式、DPO/RLHF 名词与边界）、开源贡献、多模态。

**差异化技能（Differentiator）**：领域结合的 RAG、记忆槽位与上下文工程、Token 与成本优化（可量化前后对比）、子 Agent 动态调度、评测体系（离线集+线上采样+人工抽检闭环）、硕博或论文（算法/对齐岗强信号）。

## 【问题】
问：不同技术背景的人（Java/Python/Go 后端、应届生、前端）转向 AI Agent，文档分别给了一条什么最短路径？

## 【回答】
文档针对五类背景给出可执行路径：

- **Java 后端转**：用 Python 实现最小 RAG + Tool Calling 服务（FastAPI），与 Java 网关通过 HTTP/gRPC 对接，降低一次性迁移风险；把「限流、熔断、幂等」映射到 Agent 多步调用；简历突出高并发+可靠性+模型服务集成。
- **Python 后端转**：给每个项目补**观测（请求 ID、每步耗时、Token 计数）与简单评测集**；补 K8s 或至少 Docker Compose 一键部署；深入 LangGraph 或自研状态机其一，讲清状态持久化与回放。
- **Go 后端转**：常见架构为 Go 网关 + Python 模型/Agent worker，或 Go 调推理 HTTP API；补 RAG 与 Agent 编排的 Python 原型再考虑 gRPC 服务化；强调低延迟链路、连接池、并发控制与 Token 预算管理。
- **应届生 / 小白**：用实习、竞赛、开源、高质量毕设缩小差距；做一条完整链路（数据→RAG→Agent→简单前端或 CLI→Docker 部署）+ 一个可展示仓库（CI、类型检查、测试、评测脚本）；优先投校招/实习/助理级 JD。
- **前端转**：用 Next.js / Vite 做 Agent 控制台（步骤可视化、工具调用日志、Token 显示）；补 Node 或 Python 一层 BFF；目标岗位可侧重「AI 应用/全栈/前端工程化 + Agent」。

## 【问题】
问：AI Agent 岗位对学历、经验与工程能力（非算法类）的要求分别是什么？

## 【回答】
**学历要求**：
- 本科及以上：绝大多数 JD 基准线。
- 硕士/博士加分：腾讯运维 Agent、对齐/研究向岗位常见。
- 实际执行：**工程岗强项目与经验可弥补学历；算法/对齐岗更卡论文与理论基础**。

**经验要求**：
- 3 年+：腾讯资深（运维 Agent）、小红书 Agent 工程师、字节（视具体 JD）。
- 3 年+（后端/AI 工程）：小红书。
- 5 年+：腾讯高级 AI Agent 开发。

**工程能力（非算法）要求分布**：

| 能力 | 说明 | 频次 |
| --- | --- | --- |
| 线上稳定性 | 超时、重试、熔断、降级、幂等 | 高 |
| 可观测性 | 日志、Tracing、Agent 步骤级指标 | 高 |
| 评测与回归 | 数据集、自动评测、Bad case 迭代 | 中高 |
| 安全与权限 | 工具鉴权、敏感操作审批 | 中高 |
| 成本意识 | Token、GPU、调用 QPS | 高（字节等显式） |

结论：**能落地、能扛线上是工程岗主线**——稳定性、可观测、评测与成本意识比单纯「会用框架」更被看重。以上数据源自文档 2026 年公开报道归纳，以实时 JD 为准。
