# 核心概念与三大路线

## 【问题】
什么是自进化 Agent（Self-Evolving Agent）？

## 【回答】
自进化 Agent 指一类能够在与环境 / 用户交互过程中**自动积累经验、提炼能力、并在后续任务中复用与提升**的智能体。简单说：让 Agent 自己越用越聪明，而不是每次都靠人工喂数据、调提示词、改模型。

它的核心诉求可以拆成三件事：
- **能存**：把交互中沉淀的有价值内容（成功模式、失败教训、可迁移技能）存下来；
- **能用**：在新任务中把存下的东西检索 / 调用 / 内化进自己的决策；
- **能进化**：经验本身是动态的，能更新、合并、淘汰，避免越攒越乱。

## 【问题】
为什么自进化 Agent 现在被重视起来了？

## 【回答】
根因是大模型本身的几个老大难问题：
- **静态知识**：训练完成那一刻起，模型对世界的认知就被冻结了；
- **上下文有限**：再长的上下文窗口也总有边界，多轮交互终究"断片"；
- **重复犯错**：今天教会它的事，明天还会再犯一遍；
- **训练贵**：每次想让模型变强，要么 SFT 要么 RL，都得重新跑一遍。

自进化 Agent 想绕开这些限制，**让经验本身成为模型能力的延伸或更新通道**。在大模型时代被重新点燃，本质是因为：LLM 本身具备总结归纳能力（能给自己写笔记）、长程交互场景有了真实需求、高质量人工标注数据越来越贵（社区探索"少人工 / 无人工"路线）。

## 【问题】
自进化 Agent 有哪三大技术路线？

## 【回答】
按"**是否更新模型权重**"和"**是否依赖人工数据**"两个维度，可划为三类：

1. **第一类：经验 / Skill 存储型**——不更新权重、依赖人工数据。代表：AutoSkill、EvoSkill、MemSkill、CoEvoSkills、SE-Agent。类比：给 Agent 配了一本"工作笔记"，模型本体不动，只在需要时翻阅。
2. **第二类：RL 训练型**——更新权重、依赖人工数据。代表：EvolveR、SAGE、SkillRL、SKILL0、SkillOS、AgentEvolver。类比：把"工作笔记"上的经验通过 RL 写进权重，让 Agent 真正"长本事"。
3. **第三类：0 数据自学型**——更新权重、不依赖人工数据。代表：Agent0、Tool-R0、Absolute Zero。类比：连"老师"都不要了，让 Agent 之间互相出题互相考试，自己跟自己打。

## 【问题】
第一类（经验 / Skill 存储型）的核心机制与代表工作有哪些？

## 【回答】
**特征**：不训练、跨会话保留上下文、文件式存储；核心是把经验沉淀为可检索 / 可复用的"技能（Skill）"。

代表工作：
- **AutoSkill**：经典双环结构（在线服务 + 技能进化循环），动态增删改查 Skill 防止库爆棚；痛点是评估缺位。
- **EvoSkill**：三 Agent 分工（Executor 记录失败、Proposer 做根因分析、SkillBuilder 落地），用 **Pareto 精英池**保证 Skill 库"精而不滥"；把"失败即学习"写进进化闭环。OfficeQA 准确率 60.6% → 67.9%。
- **CoEvoSkills**：Generator + Verifier 双子星，给每条 Skill 配"考官"，测试驱动 Skill 进化（Surrogate 廉价验证 + Oracle 昂贵验证）；结论 **self-evo 优于 cross-model transfer**（Skill 与模型"风格"耦合）。
- **SE-Agent**：多策略轨迹横向融合（Crossover / Transfer / Restructure），区别于所有 self-refine 的纵向总结；SWE-Bench 最高 **+55% 相对改善**。

**这一类统一痛点**：看似不训练，其实仍要训练数据；"总结"这一步被严重低估。

## 【问题】
第二类（RL 训练型）的关键进展，尤其 SkillRL / SKILL0 / SkillOS 是什么？

## 【回答】
通过 RL 训练直接更新模型权重，让模型从根本上变强，是当前学界与工业界的主流方向。

- **SkillRL**：用强模型（o3）蒸馏 Skill，再通过 RL 训练弱模型（Qwen2.5-7B，Cold-start SFT → GRPO）学会使用，递归进化技能库。ALFWorld 89.9% vs GRPO 基线 77.6%（**+12.3%**）；本质是"蒸馏"而非"进化"。
- **SKILL0**：把 Skill 从推理时的"外挂上下文"**内化到模型参数**，实现零样本执行（每步 < 0.5K tokens）。三阶段渐进课程（Stage1 6 条 → Stage2 3 条 → Stage3 0 条）完成"使用技能 → 内化技能"的范式转变；它是 SkillRL 的"下游消费者"。
- **SkillOS**（最有启发性）：训练专门的 **Curator**，通过 RL 学会如何**增 / 改 / 删 SkillRepo**，而不是直接学如何使用 Skill。两个关键结论：①**训练过的小模型总结者 > 冻结的大模型总结者**（RL 训练的 Qwen3-8B Curator 超过冻结的 Gemini-2.5-Pro）；②**不动解题者，性能也能涨**——"换 Curator"是比"换 Executor"更轻量的优化路径。

## 【问题】
第三类（0 数据自学型）如何工作？

## 【回答】
完全不要人工标注数据，靠 Agent 之间互相出题 / 解题闭环：

- **Agent0**：Curriculum Agent（RL 出题，reward = 答题者不确定性 + 工具使用频率）+ Executor Agent（RL 解题）；评估以数学类（GSM8K、AIME）为主。
- **Tool-R0**：类似 Agent0，但面向通用工具使用；reward 含合法性（不能有幻觉 tool）、难度（不能太难太简单）。
- **Absolute Zero**：单个模型同时扮演出题人和解题人，以**代码执行器为唯一验证来源**，完全不碰任何外部数据；题目为 [输入, 代码, 输出] 三元组，随机删除一个让答题 Agent 猜测。

**隐患**：题目答案多为出题 Agent 自己多采样投票的 **sliver answer**，可靠性存疑；因此最好有自动化判断标准（如 Absolute Zero 的代码执行器），且出题难度（太难学不懂、太简单学不到）的 reward shaping 是核心难点。

## 【问题】
横向对比与范式演进的关键洞察是什么？

## 【回答】
SkillRL → SKILL0 → SkillOS → AgentEvolver 的范式演进脉络：
**强模型提炼知识 → 弱模型 RL 学会使用 → 内化进参数 → 训练 Curator 管理 → 全链路自主（自出题 + 自解题 + 自总结）**。

最被低估的关键模块是"**总结者**"：几乎所有工作都把总结外包给冻结的大模型 / 闭源 API，只有 SkillOS 真正把 Curator 当作主训练对象。研究空白在于 **"题目自动生成 + 训练总结者"的右上方象限**目前没有工作覆盖；此外"横向总结（SE-Agent 多次采样）"与"纵向总结（历史轨迹）"的融合也是开放问题。

## 【问题】
自进化 Agent 的本质问题是什么？

## 【回答】
如何**让 Agent 在没有人工干预的情况下，把交互的副产物转化为下一次更强的能力**。无论是把经验存进文件、训进权重，还是让 Agent 之间互相出题，所有路径都在回答这一个问题的不同侧面。
