# 轻Agent 与重Agent 定义、差异、边界

## 总览

区分核心：谁来决定整体任务执行路径（全局规划权）。

1. **轻 Agent（受限 Agent / Workflow 约束 Agent）**：全局流程骨架是人提前定义好的（DAG/固定步骤顺序），Agent 没有权限新增、调整整体步骤；只负责**单步骤内部的局部推理、参数解析、工具调用、校验重试、分支选择**。
2. **重 Agent（通用自由 Agent）**：没有预设完整流程骨架，拿到顶层目标后，**自主做全局任务拆解、动态规划完整执行路径，可以随时增删、调整子任务顺序**，全权决定下一步做什么。

共同点：两者都具备 LLM 推理 + 记忆 + 调用 Skills 的能力；都属于 Agent 范畴，不是纯 Skill 编排。

差异点：**全局规划权限是否受限**。

## 一、详细对比表

| 维度 | 轻Agent（受限） | 重Agent（通用自由） |
|---|---|---|
| 全局流程 | 整体步骤、允许执行顺序由开发者提前定义（DAG/Workflow骨架），Agent不能新增大步骤、调换主干顺序 | 无固定主干流程，由LLM自主拆解目标，动态生成完整执行计划，可随时变更步骤 |
| 决策范围 | 局部决策：单步内参数提取、子分支判断、重试、异常兜底 | 全局决策：任务拆解、子任务排序、跨步骤调度、动态新增工具调用 |
| 可控性 | 高：主干流程不变，可审计、可限流、可权限管控，不容易越权 | 低：执行路径不可预知，容易出现幻觉、无效工具调用、越权操作 |
| 算力成本 | 偏低：规划范围小，prompt短，工具调用次数可控 | 偏高：多轮规划+反思，大量工具轮次，不稳定，成本波动大 |
| 适用场景 | 企业标准化业务：报销、工单处理、数据校验、固定审批流程、报表生成（业务有标准Workflow） | 开放探索类任务：竞品调研、完整项目开发、文献综述、根因探索、自定义复杂报告 |
| 典型架构 | DAG工作流（固定主干） + Agent作为单步执行器 | Planner规划器 + 反思器 + 工具池（无固定DAG） |
| 风险 | 风险低，幻觉被约束在单步内部 | 风险高，可能出现无效循环、错误规划 |

## 二、举例直观区分（同一个业务场景对比）

场景：客户售后工单处理，业务规范固定：接收工单→核查订单→判定责任→生成回复→归档。

**轻 Agent 方案**：人工定义主干 DAG：必须按【接收→查订单→判定→回复→归档】顺序执行，不允许跳过、新增主干步骤。

Agent 能干什么：
- 从用户自由文本工单里提取订单号（非结构化解析）
- 根据订单状态动态选择不同的回复模板
- 调用查询 Skill，查不到数据自动重试一次

Agent **不能做**：自主跳过归档、主动新增“打电话通知客户”这种流程外步骤。

**重 Agent 方案**：只给顶层目标：妥善处理这条售后工单，让客户满意，输出归档记录。

Agent 自主规划：
1. 先解析工单信息
2. 判断是否需要查询订单
3. 判断是否需要调用退款工具
4. 判断是否需要追加调用短信通知
5. 如果沟通失败，自主新增升级人工子任务

主干步骤完全由模型实时生成，不受固定 DAG 约束。

## 三、容易混淆的关键点澄清

### 1. 不是按模型大小分轻重！

≠ 大模型=重 Agent，小模型=轻 Agent。

轻/重是**架构和权限设计概念**，和底层 LLM 参数量无关。同一个大模型，可以封装成轻 Agent（套 DAG 骨架限制全局规划），也可以做成重 Agent（自由规划）。

### 2. 轻 Agent ≠ 静态 Skill 编排

- 静态 Skill 编排：连分支、参数都全部硬编码，**没有 LLM 推理**
- 轻 Agent：主干固定，但单步内部交给 LLM 做动态推理、工具调度、重试，**有 LLM 决策能力**

### 3. 中间态：半受限 Agent（行业很常见）

给定可选子任务列表（允许调用哪些 Skill），但不强制执行顺序。

例如：允许 Agent 自由选择【搜索、读取文档、计算】三个工具，但不能调用发送邮件、修改数据库等高风险工具。

介于轻、重之间，一般归类为**受限 Agent**，不归为重 Agent。

## 四、选型口诀补充（承接上一轮）

1. 主干流程固定，只需要单步内动态推理 → **轻 Agent（推荐企业业务首选）**
2. 无既定流程，需要自主拆解全局任务、动态调整执行顺序 → **重 Agent，谨慎上生产**
3. 全流程、全分支都能写死，不需要 LLM 推理 → **静态 Skill 编排，不用 Agent**

## 五、生产落地建议

企业内部业务系统，**优先轻 Agent**：用 Workflow/DAG 管住主干流程、权限、审计；把复杂的局部分支、非结构化解析、重试交给轻 Agent。

重 Agent 一般只用于离线分析、调研类非核心链路，很少直接对接线上核心业务。
