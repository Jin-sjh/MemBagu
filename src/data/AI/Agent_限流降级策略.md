# 限流降级策略

## 【问题】
突发流量可能打垮系统，高并发下怎么限流和优雅降级？

## 【回答】
分级限流 + 多级降级（以下为该文档工程实践口径）：
- **限流层次**：API 网关全局限流、租户级 QPS 配额、用户级（如每用户每分钟 20 次）。
- **算法**：Redis + 令牌桶，桶容量=2×配额以扛突发。
- **降级四级**：L0 正常 → L1 关非核心（推荐/个性化）→ L2 模型降级（复杂查询也走快速模型）→ L3 只返缓存/FAQ、不调 LLM。
- **触发条件**：QPS>80%阈值升 L1；LLM 错误率>10% 升 L2；CPU>90%/内存>85% 升 L3。
- 要点：**限流保护核心链路不被打垮，降级用"牺牲体验换可用"；降级响应 < 200ms**。
