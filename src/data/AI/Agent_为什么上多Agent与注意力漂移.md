# 为什么上多Agent与注意力漂移

## 【问题】
单 Agent 和多 Agent 的本质区别是什么？什么时候该上多 Agent？

## 【回答】
本质区别**不在「调几次模型」，而在是否显式建模角色、通信与治理**。
- **单 Agent 适合**：任务边界清晰、工具少、强实时、成本极度敏感的场景。
- **多 Agent 适合**：任务可分解、需要不同专业视角、需要并行、需要权限隔离（例如代码执行与对外发布分离）、需要可观测的分阶段产出的场景。

追问「多 Agent 会不会更贵」：**通常 Token 与调用次数上升**，但若通过**小模型子任务 + 大模型仲裁、并行缩短时间、减少无效重试**，总成本未必更高，需要按业务度量。

## 【问题】
什么是「注意力漂移」？多 Agent 怎么缓解？

## 【回答】
注意力漂移指模型在**长上下文或多目标提示下，对关键约束的关注度下降**，导致输出偏离要求（常表现为「lost in the middle」，模型对中间段落的有效利用率弱于首尾）。
多 Agent 缓解方式：
- **拆分子目标**，使每个子上下文更短；
- **专职角色**减少单提示中的目标数量；
- **中间结果结构化**（JSON / 状态机）减少自然语言堆砌。

不用多 Agent 的缓解手段：摘要、检索注入关键句、约束前置、链式调用加校验器。

## 【问题】
「单 Agent + 多个工具」和「多 Agent」怎么取舍？

## 【回答】
若只需**统一策略调不同 API**，单 Agent + 工具即可；若需要**角色隔离、并行、对抗评审、组织流程**，多 Agent 更合适。
多 Agent 的价值来自四点：**拆上下文、专业化、并行、隔离失败**；单 Agent 的瓶颈是注意力与能力边界问题（一个全能选手往往样样稀松，单一 system prompt 难同时覆盖严谨规划、创意发散、代码执行、合规审查）。
