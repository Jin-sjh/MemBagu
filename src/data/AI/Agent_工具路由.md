# 工具路由

## 【问题】
工具数量多的时候，什么时候必须上工具路由？

## 【回答】
一次性把所有 description 塞进上下文会**费 token、干扰模型、增加误选**。当工具数量导致上下文膨胀、误选率上升或延迟/成本明显增加时就要考虑路由；**常见从几十个工具起考虑**（具体阈值依赖模型与描述长度，视情况而定）。方法包括向量检索、分类/意图模型、层级目录（先选类再选工具）、规则前缀（如用户以 `/db` 开头走数据库类）。

## 【问题】
基于向量检索的工具路由有什么缺陷？怎么改进？

## 【回答】
缺陷：**极依赖描述质量**；边界 case 需加规则；专有名词（OOV）匹配弱。改进：**混合检索（关键词 + 向量）**、同义词表、用户域特征、日志驱动迭代描述、加轻量分类器。

兜底策略：Top-K 调大、加一层 LLM「是否适用」二分类、允许用户澄清、保留「通用搜索」工具作后备。
