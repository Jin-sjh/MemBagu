# Reflexion自我反思

## 【问题】

什么是自我反思（Reflexion）？它的核心原理是什么？

## 【回答】

**自我反思（Reflexion）是通过语言反馈来强化基于语言的智能体（Agent）的框架**，由 Shinn et al. (2023) 提出，是一种"**口头"强化学习的新范例**，将策略参数化为智能体的记忆编码与 LLM 的参数选择配对。简单说，**Reflexion 让智能体从自身的错误中学习**——把环境反馈转换为语言形式的"自我反思"，为下一轮尝试提供上下文，从而快速有效地改进决策。**核心原理**：将来自环境的反馈（自由形式的语言或标量）转换为语言反馈，即 **self-reflection（自我反思）**，为下一轮 LLM 智能体提供上下文，帮助其快速有效地从错误中学习。

## 【问题】

Reflexion 由哪三个组件组成？各有什么角色？

## 【回答】

自我反思由三个不同的模型组成：

| 组件 | 角色 | 功能 |
|------|------|------|
| **参与者（Actor）** | 生成文本和动作 | 根据状态观测量生成文本和动作，在环境中采取行动并接受观察，形成轨迹。**链式思考（CoT）** 和 **ReAct** 被用作参与者模型，并添加记忆组件提供额外上下文 |
| **评估者（Evaluator）** | 评价输出 | 对参与者输出进行评价，将生成的轨迹（短期记忆）作为输入，输出奖励分数。根据任务使用不同奖励函数（决策任务使用 LLM 和基于规则的启发式奖励） |
| **自我反思（Self-Reflection）** | 生成语言强化线索 | 由大语言模型承担，帮助参与者自我完善，利用奖励信号、当前轨迹和持久记忆生成具体且相关的反馈，存储在记忆组件中（长期记忆） |

## 【问题】

Reflexion 与 ReAct 有什么关系？工作流程是什么？

## 【回答】

**Reflexion 拓展了 ReAct 框架**，通过引入三个关键机制增强其能力：**自我评估（Self-Evaluation）**、**自我反思（Self-Reflection）**、**记忆组件（Memory）**。**工作流程（迭代循环）**：

1. **定义任务**（Define the task）
2. **生成轨迹**（Generate a trajectory）
3. **评估**（Evaluate）——由评估者对轨迹打分
4. **执行自我反思**（Perform self-reflection）——生成语言反馈并存入长期记忆
5. **生成下一条轨迹**（Generate the next trajectory）——利用反思结果改进

这一流程使智能体能**通过试错（trial-and-error）不断学习**，逐步优化行为。

## 【问题】

Reflexion 的实验表现如何？何时适合使用？

## 【回答】

**实验表现**：序列决策（AlfWorld）上 **ReAct + Reflexion 完成 130/134 项任务**，显著优于单独 ReAct；推理（HotPotQA）上 **Reflexion + CoT 性能优于仅 CoT** 和具有情景记忆的 CoT；编程（MBPP、HumanEval、Leetcode Hard）上编写 Python 和 Rust 代码时通常优于之前的 SOTA 方法。

**最适合以下情况**：1. 智能体需要**从试错中学习**（决策、推理、编程）；2. **传统强化学习失效时**——Reflexion 不需要微调底层语言模型，在数据和计算资源上更高效；3. 需要**细致入微的反馈**——语言反馈比传统 RL 的标量奖励更具体；4. **可解释性和直接记忆很重要**——提供更可解释、更直接的情景记忆形式。

**局限性**：**依赖自我评估能力**（需准确评估自身表现并产生有用反思）；**长期记忆限制**（使用最大容量的滑动窗口，复杂任务可能需要向量嵌入或 SQL 数据库）；**代码生成限制**（测试驱动开发在指定精确输入输出映射方面存在限制）。
