# Agent工作流程

## 【问题】

描述一下 Agent 的典型工作流程（核心循环）。

## 【回答】

经典范式是 **Thought（推理）→ Action（行动）→ Observation（观察）→ … → Final Answer** 的多轮控制循环，落地通常由「编排层（Orchestrator）」驱动：解析模型输出、执行工具、把结果写回上下文，直到满足停止条件。工程上可拆成五步：

1. **输入处理**：意图识别、指代消解、安全过滤、加载相关记忆与文档。
2. **任务分解**：生成子任务列表或决策树；复杂任务可配合 Human-in-the-loop 确认里程碑。
3. **工具选择与调用**：由模型或路由模块选择工具，执行器做鉴权、限流与结果规范化。
4. **结果整合**：合并多源信息、解决冲突（如时间更新的数据优先）。
5. **输出生成**：面向用户的自然语言答案 + 可选引用与操作轨迹（便于审计）。

## 【问题】

怎么避免 Agent 在工具调用之间「迷失」（跑偏、死循环）？结果冲突怎么整合？

## 【回答】

防迷失：

- 明确**停止条件与最大步数**硬上限；
- 维护**任务清单（todo）与当前子目标**；
- 每步输出要求**结构化（JSON）**；
- 关键步骤**强制验证**（单元测试式检查、二次 LLM 审核）。

结果冲突整合：按**优先级规则**（权威源 > 时间新 > 多源一致），让模型显式输出「冲突说明」，必要时触发人工。
