# Harness Engineering

## 【问题】
什么是 Harness Engineering？它在 AI 工程五层演进中处于哪一层？

## 【回答】
Harness（脚手架/框架）是围绕模型搭建的**周围结构**——工具、护栏、跨会话状态、指令文件。AI 工程是一层层往外叠的演进：**Prompt Engineering**（一次对话怎么说）→ **Context Engineering**（往模型塞哪些信息）→ **Harness Engineering**（周围结构/工具/护栏/跨会话状态）→ **Loop Engineering**（单个智能体自循环）→ **Graph Engineering**（多智能体组织）。

## 【问题】
为什么模型变强后 harness 要做"减法"？"冗余从中性变负数"怎么理解？

## 【回答】
两家头部厂商独立收敛到同一个方向——**减法**：Anthropic 一次删掉 Claude Code 系统提示词的 **80% 以上**，编码评测无可测量损失；作者团队对 tdsql-harness 重构时删掉**根指令 61%、skills 40%、agent 从 10 个减到 6 个**。

关键质变是**冗余从中性变成了负数**：
- 弱模型时代，多写一句话最坏是浪费 token；今天，**多写一句话可能覆盖掉模型自己更好的判断**。
- OpenAI 的机制说明：旧 prompt 过度规定流程，在 GPT-5.5 上会"**引入噪音、缩小模型的搜索空间、导致机械化回答**"。"缩小搜索空间"是这轮变化的技术内核。
- 官方处置建议是**"删除，而不是改写"**——显式验证指令（final verification step、use a subagent to verify）在 Claude Opus 5 上会导致过度验证，删除后质量无损失还省 token。
- OpenAI 迁移建议：不要逐条搬运旧 prompt，应**从一个全新的基线开始**，先写"能保住产品契约的最小 prompt"，再针对真实样例调优。**把旧指令当作待验证的负担，而不是资产。**

## 【问题】
为什么"保守一点""只报高危问题"这类措辞在强模型上会削减召回？强调语与负面指令为何反噬？

## 【回答】
- **程度副词会被字面执行**：prompt 里写"只报高危问题"或"保守一点"，模型会照字面执行、报得更少。正确做法是让它**全报，再另开一轮过滤**。"保守一点"在人类之间是程度副词，在指令遵循能力强的模型那里是一条会被严格执行的规则——**你以为在调节风格，实际在削减召回**。
- **强调语反噬**：`CRITICAL: You MUST use this tool when...` 应降级为普通的 `Use this tool when...`，因为新模型对系统提示词更敏感，激烈措辞会导致**过度触发**；`If in doubt, use [tool]` 这类兜底句现在是过度触发的主要来源。
- **负面指令反噬**："不要思考 / 不要推理"这类规则要直接删掉，反而会增加内部标签泄漏到可见输出的概率；**"点名负面项"比"笼统表述"效果更差**。

## 【问题】
模型变强后，指令编写正在变的四件事是什么？

## 【回答】
1. **规则 → 判据**：穷举式禁令必然有覆盖不到的边界；判据把边界判断交回给模型（它读得到上下文，你写规则时读不到）。
2. **前置全量上下文 → 渐进式披露**：详细指引从常驻系统提示词挪进**按需加载的 skill**；skill 只有元数据（名字+描述，约 100 token）常驻，正文触发时才读入。
3. **示例 → 接口设计**：把工具接口本身设计好（如状态字段枚举 `pending / in_progress / completed`），比给一堆示例更有效。对足够强的模型，**示例会成为约束**——因为它比你给的例子更有想象力。
4. **简单 markdown 规格 → 更丰富的引用物**：用 HTML 产物、测试套件、函数签名、评分表（rubric）替代纯文字描述；**代码和测试是可执行的规格**，不存在解释歧义。

案例——prefill 是怎么消失的：prefill（预填充助手回复开头强制输出格式）是多年标准技巧，从 **Claude 4.6 开始从 API 层面直接移除**，带 prefill 的请求返回 400。**脚手架不是被优化掉的，是它防御的那个问题不存在了。**

## 【问题】
怎么判断一条 harness 指令"该不该存在"？

## 【回答】
- Anthropic 判据：**"Claude 本来就会写代码，也能读你的代码库。一个复述模型默认行为的 skill，只增加上下文，不增加价值。"**
- Addy Osmani 删除判据：**"这条信息，agent 读你的代码库能不能找到？能找到就删。"** 该删：目录结构、架构概览、技术栈描述（都能通过读代码发现）；该留：`用 uv 管理依赖`、`跑测试必须加 --no-cache 否则会有假通过`、不明显的约定、运维坑。
- **冗余的真正代价不只是 token**：你加了一个文件，agent 读了它又去读真实代码确认，就得**调和两个事实来源**——制造第二个事实来源比浪费上下文严重；代码会变、描述不会跟着变，**过期的文档比没有文档更危险**。
- 关键概念：**"上下文窗口是公共资源"**（The context window is a public good）。
- 作者团队的机械判据：**"一个没有本次会话记忆的 agent 读到这一行，行为会怎么变？答不出来就删。"** 必出局的三类——**元评论**（"这里以前出过 bug""目前还不完善"）、**自我辩护**（"这就是本 skill 存在的理由"）、**防御性否定**（"这不是指某某"）。

## 【问题】
MUST/NEVER 等绝对措辞应该留给什么？"路径放开、验收收紧"怎么理解？

## 【回答】
- OpenAI 的分界线：**MUST / NEVER 等绝对措辞只留给"真正的不变量"（true invariants）**；判断题（何时搜索、何时追问、何时用工具、何时继续迭代）一律改写成决策规则。作者团队保留绝对措辞的地方只剩一类：**不可逆动作**——commit、push、MR 合入、deploy、workspace 之外的删除。
- **正例优于禁令**：与其写一堆"不要怎样"，不如给一个你想要的样子的正面例子。
- **放开的是路径，收紧的是验收**——只做前一半就是放羊。OpenAI 原话：GPT-5.5 最强时，prompt 定义 **target outcome、success criteria、constraints** 和 available context，然后**让模型自己选路径**——四项里有三项必须写死，只有"路径"留给模型。**"给目标而不给步骤"不是写得更少，而是把笔墨从"怎么做"挪到"怎么算做完"。**
- Addy 对 workflow 的定义：skill 是一个工作流，**真正有价值的不是那些 markdown，是退出条件**；证据 = 绿色的测试结果、截图、日志、评审通过，**没有证据，这一步就不算完成**。
- 归结：**用判据而不是步骤，但判据必须能被机械判定**。"代码质量要好"不是判据（产不出证据）；"测试变绿 / 产物存在 / diff 为空 / 命令 exit 0"才是。例外：操作脆弱性（如数据库迁移）需要写死路径——**判据是操作的脆弱性，不是任务的重要性**。

## 【问题】
"先建裁判，再写内容"（Create evaluations BEFORE writing documentation）是什么？

## 【回答】
Anthropic 官方 skill 指南中**价值最高、最容易被跳过的一条**。五步流程：
1. **不带 skill 跑一遍**，记录具体的失败（不是"效果不太好"，是"它在第三步漏掉了 X"）。
2. 针对 gap **建三个评测场景**。
3. 建立 **baseline**，量出没有 skill 时的表现。
4. 写**刚好够**填补 gap 的最少内容。
5. **迭代**，对照 baseline 看有没有真的变好。

副产品：每条规则天然绑定了它防御的具体失败——成为判断"规则是否已过期"的唯一依据。**"最少内容"不是靠写的人把握分寸，而是由评测反推**：能让评测从不通过变成通过的内容就是必要的，多出来的都是待辩护的。

## 【问题】
"能沉降到工具层的，就别留在指令层"是什么意思？

## 【回答】
- Addy：**把 AGENTS.md 当成一份"你还没修掉的摩擦"的清单**。当 agent 反复卡在同一个地方时，**先去修根因**（重构代码、加 linter 规则、补测试），穷尽之后才考虑往指令文件里加话。
- OpenAI 用 Codex 交付了约一百万行代码的生产 beta 产品（全程无人手写代码），做法是**通过强制不变量，而不是微管理**——用 custom linter 和 structural test 强制，不是靠 prompt 说服；他们的 AGENTS.md 只有约 100 行，是"一张地图，指向别处更深的事实来源"——**是目录，不是百科全书**。
- 一条容易记的分工：**指令层的强度取决于模型当下怎么读它；工具层不取决于。** 指令文件应该越修越短——因为内容在持续沉降。

## 【问题】
harness 内容的 L0/L1/L2/L3 四层归属是什么？自建 harness 的立足点在哪？

## 【回答】
| 层级 | 内容 | 归宿 |
|------|------|------|
| L0 | 通用编码事实（语言语法、框架 API） | **被模型内化** |
| L1 | 通用 agent 能力（执行循环、上下文管理） | **被平台吸收** |
| L2 | 组织特有的流程与工具（内部系统用法、部署流程） | **迁移**（从指令层沉降到工具层） |
| L3 | 价值排序、私有 context、主观 oracle（什么样算"够好"） | **永不内化** |

**自建 harness 的立足点在 L2 和 L3，不在 L1。** 作者团队删掉的六类东西全部落在 L0/L1；剩下的 6,400 字符全部落在 L2/L3。

## 【问题】
为什么 L3（价值排序、私有 context、主观 oracle）永不内化？

## 【回答】
- **理由一：信息不可达。** 这些信息**物理上不在模型能到达的地方**：不在公开语料（否则每个组织都会是一样的答案），也不在你的 repo 里（否则 grep 就能拿到），只存在于人的头脑和组织运作中。判断保值判据——问**"这条信息的源头在哪里"**：在公开语料→会被内化别写；在 repo/运行环境→会被工具拿到别写；**在人的头脑或组织结构里→永远是你的责任**。
- **理由二：责任不可转移。** 比理由一更硬——信息不可达可以靠"把信息补齐"缩小，但责任不行。**"Only people inherit consequence."**（只有人能继承后果）就算把所有信息都给了模型，责任也不会转移——出了事被问责的是人，这是**社会结构问题**，连理论上都无法被技术进步消解。
- 人必须持有的三件东西（可直接当 gate 设计清单）：**Verdict（裁决）/ Answerability（可答辩性）/ Accountability（可问责性）**。

## 【问题】
什么会过期、什么不会过期？到期审计怎么做？

## 【回答】
- 统一的判别式：**凡是为了补模型能力缺口而写的，都会过期，只是早晚。** 翻出任意一条指令问它"为什么存在"，如果理由是"模型记不住 / 模型不会主动做 / 模型容易漏"——它已经在到期队列里了。
- **不会过期的三件具体的事**：①**验收标准**——什么算"做完了""够好了"，每个团队不一样；②**授权边界**——什么能自己做、什么必须停下来找人、什么绝对不能做；③**只有你们知道的东西**——私有 context、隐藏约定、历史决策的理由。它们不变不是因为"它更难"，而是因为**信息源头在人那里、责任只能由人承担**。
- **到期审计**：每隔一个模型代际做一次，问 Anthropic 那个问题——**what can I stop doing?** 重点查理由是"模型记不住 / 不会主动做 / 容易漏"的条目。
- Addy 的**棘轮法（ratchet approach）**：**只在观察到真实失败之后才加约束**；规则必须能追溯到真实发生过的错误。绝大多数 AGENTS.md 只增不减，根因不是懒，而是**这些规则当初就没写清防的是什么**——说不清防什么的规则，从写下来的那一刻就已经无法被淘汰了。

## 【问题】
为什么 harness 不会消失、而是在迁移？L2 的价值到底是什么？

## 【回答】
- **"Counterintuitively, harnesses don't shrink; they migrate."**（harness 不会收缩，它在迁移）更好的模型消除某些脚手架，但会启用需要不同脚手架的新能力。
- 开源 harness 框架能给你的大部分是 **L1**（执行循环、状态管理、subagent 编排、上下文管理）——恰恰是**最会被平台原生吸收、最不保值**的一层。很多团队自建 harness 力气全花在 L1 上，是**投入最大、贬值最快**的地方。
- **L2 的价值是"让 agent 能做"，不只是"告诉 agent 怎么做"**：通过 MCP 工具、封装脚本、固化的操作流程，agent 获得**操作内部系统的能力**（查工作项、触发流水线、登录测试集群拉日志、处理评审意见后回写状态）。这是**能力接入，不是知识注入**——模型能力提升会让"知识"越来越强，但**不会让它自己跨到"能力"那一边**。
- **Anthropic 自己就是样本**：Claude Code 系统提示词删到 20% 后剩下的是产品级上下文、团队意见、gotchas、验证 skill、安全边界——全部是 L2 和 L3；他们统计**验证类 skill 是内部对产出质量影响最可测量的一类**（验收标准是组织特有的、模型拿不到的信息）。
- 自建 harness 是在**偿还意图债**：agent 的每个 session 都是冷启动——凡是你没有外化成它能读到的文档的东西，它就没有；你要为每一次未记录的决策重复付费。为 agent 沉淀 L2/L3 本质上是在补一直欠着的工程基础设施。

## 【问题】
自主度的上界是什么？gate 该怎么设计？

## 【回答】
- **back pressure**：**"You can only hand a loop as much autonomy as you can cheaply and reliably verify, and not one inch more."**（你能交给一个循环的自主度，上限就是你能廉价且可靠地验证的那么多，一寸都不能多）上界绑定的是**验证能力**，不是任务重要程度、也不是模型能力。
- 配套三个判定问题：①**多快能知道我们错了？** ②**多干净能撤销？** ③**什么能证明我们是对的？**
- 反模式：过早给自主权、只给摘要当验收、把不可逆动作交给 agent。
- **验证，而不是生成，才是真正的瓶颈**：启动 agent 只要一句话，收口一个 agent 一点也不便宜。当生成速度超过能验证的速度，积累的是**认知债**——代码看着干净、测试全绿，但没有人真正理解它；它不通过摩擦暴露自己，**滋生的是虚假的信心**。
- **gate 的数量上限，等于人能真正判断的数量上限**。人在 gate 面前会退化成快速点头，对策不是减少 gate，而是**让每个 gate 便宜到能真判**：把需要裁决的事项、证据和推荐前置，全文和 diff 作为可选读附录。一个人判不动的 gate 等于没有 gate，而且更糟——制造了"已经审过"的假象。

## 【问题】
自我偏好偏差（self-preferential bias）是什么？为什么独立 reviewer 的价值不衰减？

## 【回答】
- Anthropic 点名单上下文推理的三个失败模式：**agentic laziness（智能体偷懒）、self-preferential bias（自我偏好偏差）、goal drift（目标漂移）**。其中自我偏好偏差是"**评价者与被评价者是同一个**"造成的**结构性问题**，不是"模型不够聪明"。
- 同一现象被多处独立观察到：模型自评时会 **confidently praise the work**（自信地夸赞自己的产出）；Addy 直白地说："写代码的那个模型给自己的作业打分，实在是太宽容了。"
- 结论：**独立 reviewer 和跨模型校验的价值，不随模型变强而衰减**。Anthropic 实测评估者价值边界只是**外移**（以前需要 QA 复核的任务现在模型能自行完成，但复杂应用仍从独立评审中获益）——**是边界移动，不是价值消失**。

## 【问题】
不可逆动作的授权原则是什么？

## 【回答】
Anthropic《Agent Harness Design: 3 Patterns》第三个模式：**不可逆动作只能由用户明示触发**。作者团队与官方独立收敛到同一结论：tdsql-harness 第四节整节就是"不可逆动作只能由用户明示触发"——**commit、push、MR 合入、deploy、workspace 之外的写入与删除**，且规定 **subagent 永久不得执行其中任何一项**。
