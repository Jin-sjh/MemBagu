## 【问题】
一面：事件冒泡和事件捕获分别是什么？事件传播顺序是怎样的？

## 【回答】
> 回答建议（资料未提供原文答案，以下为根据公开资料的整理）

DOM 事件传播通常分为三个阶段：**捕获阶段、目标阶段、冒泡阶段**。捕获阶段从 `window`、`document` 等祖先节点向目标节点传播；到达目标后执行目标节点上对应的监听器；随后在支持冒泡的事件中，从目标节点沿祖先链向上冒泡。

通过 `addEventListener(type, listener, { capture: true })` 注册捕获监听器；默认 `capture` 为 `false`，监听冒泡阶段。目标节点上的捕获监听器与非捕获监听器都可能执行，具体顺序受阶段和注册方式影响。并非所有事件都会冒泡。

## 【问题】
一面：什么是事件委托？它与事件冒泡有什么关系？

## 【回答】
> 回答建议（资料未提供原文答案，以下为根据公开资料的整理）

**事件委托**是把多个子元素的事件处理器交给共同的祖先元素处理。子元素触发事件后，事件通过冒泡到达祖先节点，祖先监听器再通过 `event.target`、`closest()` 等方式判断实际触发元素并分派逻辑。

它利用的是事件冒泡，因此适用于会冒泡的事件。优点是减少监听器数量，也能处理后来动态插入的子元素；需要注意目标判断、嵌套元素、事件冒泡行为，以及在适当时机移除祖先监听器。

## 【问题】
一面：Vue2 和 Vue3 的响应式原理有什么区别？

## 【回答】
> 回答建议（资料未提供原文答案，以下为根据公开资料的整理）

Vue2 主要通过 `Object.defineProperty` 为对象已有属性定义 getter 和 setter，在读取时收集依赖，在写入时通知相关依赖更新。Vue3 的响应式系统主要使用 `Proxy` 代理对象，在读取、写入、删除等操作时进行追踪和触发，并通过 `Reflect` 执行对应的默认操作。

因此，Vue3 可以在代理层面覆盖属性新增、删除及数组索引等操作，也能更自然地处理对象结构变化。Vue3 还使用 `ref` 等机制处理基本类型响应式；`reactive` 通常用于对象。两代 Vue 的依赖追踪、调度及组件更新实现不止是 API 替换，回答时可概括核心差异，并结合依赖收集和触发过程解释。

## 【问题】
一面：Vue2 使用 `Object.defineProperty` 存在哪些局限？Vue3 使用 `Proxy` 后有什么改进？

## 【回答】
> 回答建议（资料未提供原文答案，以下为根据公开资料的整理）

`Object.defineProperty` 是对单个属性设置 getter/setter，Vue2 初始化时需要遍历已有属性。**新增或删除对象属性不能被既有 getter/setter 自动拦截**，Vue2 通常需要 `Vue.set` / `vm.$set` 和 `Vue.delete`；数组通过索引直接设置或修改 `length` 也有检测限制，Vue2 对部分数组方法作了拦截处理。

`Proxy` 代理整个对象，可拦截属性读取、赋值、删除、存在性检查等操作，因而能覆盖新增、删除属性等情形，也减少逐属性定义访问器的需要。代价是旧浏览器兼容性要求更高；代理对象与原始对象是不同引用，使用时也需理解 `reactive`、`ref` 和解包等规则。

## 【问题】
一面：你了解哪些常见的 Web / 前端安全问题或攻击？

## 【回答】
> 回答建议（资料未提供原文答案，以下为根据公开资料的整理）

可以举例说明 **XSS（跨站脚本）**、**CSRF（跨站请求伪造）**、点击劫持、敏感信息泄露、不安全的依赖或第三方脚本，以及不安全的跳转或 URL 处理。回答时说明攻击面和影响，例如 XSS 可能让恶意脚本在受害者页面上下文中执行；CSRF 利用浏览器自动携带凭据诱导用户发出非预期请求。

前端安全需要和服务端配合：输入校验、按上下文安全输出、合适的认证与授权、CSRF 防护、HTTPS、安全的 Cookie 属性、内容安全策略、依赖治理和敏感信息最小化等。不要把前端校验当作服务端安全边界。

## 【问题】
一面：XSS 应该如何防护？（原问题未完整保留，依据直接回答恢复）

## 【回答】
> 回答建议（资料未提供原文答案，以下为根据公开资料的整理）

主要原则是**避免把不可信输入当作可执行代码或 HTML 输出**。普通文本使用框架默认的文本插值或安全 DOM API；确需展示富文本时，使用可靠的 HTML 清理器按允许标签和属性做白名单过滤。避免把不可信数据传给 `innerHTML`、`eval`、危险 URL 或类似执行入口。

可再结合内容安全策略（CSP）降低注入脚本执行风险，并设置 HttpOnly 等 Cookie 属性减少脚本读取会话凭据的机会。CSP 和 HttpOnly 是纵深防护，不能替代输出编码与 HTML 清理；不同输出上下文需要采用匹配的编码或处理方式。
