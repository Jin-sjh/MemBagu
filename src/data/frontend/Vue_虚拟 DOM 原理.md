# 虚拟 DOM 原理

## 【问题】说说虚拟 DOM 的实现原理。

## 【回答】

我可以从**是什么、为什么、怎么做**三个方面来回答：

1. **虚拟 DOM 本质上就是用一个轻量的 JavaScript 对象，来模拟真实 DOM 树的结构**，包括标签名、属性、子节点等。它不依赖浏览器环境，操作成本远低于真实 DOM。

2. 它的核心流程分为三步：
   - 第一步，页面渲染时，先根据数据生成**虚拟 DOM 树**；
   - 第二步，当数据发生变化时，生成**新的虚拟 DOM 树**，并通过**diff 算法**和旧树做**同层对比**，找出最小差异；
   - 第三步，把这些差异**批量更新到真实 DOM**上，避免频繁操作 DOM 带来的重绘重排，从而提升性能。

3. diff 算法的核心思想是：
   - **只同层比较，不跨层级**；
   - **节点类型不同直接替换，不继续比较子节点**；
   - 配合**key**来复用节点、减少 DOM 创建和删除。

所以虚拟 DOM 的本质，就是**用 JS 计算成本换取 DOM 操作成本**，同时让框架实现**跨平台**和**声明式渲染**更方便。

---

## 极简版（15 秒回答，适合紧张时）

虚拟 DOM 就是用 JS 对象模拟真实 DOM 树。当数据变化时，通过 diff 算法对比新旧虚拟 DOM 树，找出最小差异后批量更新到真实 DOM，避免频繁操作 DOM 带来的性能问题。diff 算法只同层比较，节点类型不同直接替换，配合 key 复用节点。本质是用 JS 计算成本换取 DOM 操作成本。

## 【问题】Vue Diff 算法是什么？有哪些核心规则？

## 【回答】

### 一句话概括
Diff 算法是**虚拟 DOM 树同层级对比**的算法，核心目的是**找出新旧 VNode 最小差异**，以最少次数操作真实 DOM，避免整棵树重新渲染，提升页面性能。

### 通用 Diff 三大核心规则

**1. 同层比较**

只做同一层级节点对比，**不跨层级对比**；如果父节点标签类型不同，直接销毁整棵子树重建，不深度对比子节点。

**2. 标签类型优先**

标签名 / 组件类型不一样，直接销毁旧节点、创建新节点；只有类型相同，才对比属性和子节点。

**3. Key 的作用**

Key 作为**节点唯一标识**，用来精准识别同一个节点，避免按 index 错位复用；能最大化复用 DOM、减少不必要渲染和移动。

## 【问题】Vue2 双端 Diff 算法是怎么实现的？

## 【回答】

Vue2 采用**双端比较 Diff**，用**头尾双指针**同时从新旧列表首尾向中间靠拢，做四轮匹配：

1. 旧头 配 新头
2. 旧尾 配 新尾
3. 旧头 配 新尾
4. 旧尾 配 新头

命中任意一种就**更新属性、递归对比子节点**，移动 DOM 位置并移动指针；

四轮都没命中，就建立**key 映射哈希表**，快速查找旧节点：

- 找到：复用节点、移动位置
- 没找到：新建节点

最后处理剩余节点：新的剩就新增，旧的剩就删除。

## 【问题】Vue3 快速 Diff 算法是怎么实现的？

## 【回答】

Vue3 优化为**快速 Diff 算法**，核心是**最长递增子序列 LIS**：

1. 先做**前后预处理**：找出头部、尾部稳定不变的节点，直接复用不用移动；
2. 只对**中间乱序部分**做处理；
3. 生成新节点对应旧列表的索引数组，求出**最长递增子序列**；
4. **在 LIS 里的节点不用移动**，不在序列里的节点执行移动、新增、删除，实现**最少 DOM 移动次数**，时间复杂度优化到 O(nlogn)，比 Vue2 乱序列表效率更高。

---

## 【问题】为什么不能用 index 当 key？

## 【回答】

用 index 做 key 时，列表**新增、删除、插入**会导致后续节点 index 全部变化：

- 虚拟 DOM 错误复用旧节点；
- 引发表单输入框内容错乱、样式绑定错乱、不必要重渲染；

**推荐用后端返回唯一 id 做 key**，保证标识稳定不变。

---

## 【问题】Vue Diff 与 React Diff 有什么区别？

## 【回答】

React Diff 是**单向深度优先遍历**，搭配 Fiber 架构可以**任务拆分、中断恢复**，适合大应用，但列表乱序下没有 Vue3 LIS 高效。

## 【问题】
虚拟 DOM 的核心价值是什么？它真的比直接操作 DOM 快吗？

## 【回答】
虚拟 DOM 的核心价值**不是绝对性能最优**，而是**更新抽象、可维护性**和**渲染目标解耦（跨平台）**：它把开发者从手写所有 DOM 增删改中解放出来，提供中间表示和跨平台 renderer。**它并不保证比手写 DOM 快**——声明式 UI 与 VDOM 带来创建 VNode、比较和调度的成本；静态 HTML 或简单局部更新未必需要它。本质是用 **JS 计算成本换取 DOM 操作成本**，并让框架实现声明式渲染更方便。

## 【问题】
key 除了性能优化，对组件状态还有什么影响？

## 【回答】
`key` 不只是性能提示，它表达**节点身份**。在列表**插入、删除、排序**时，稳定的 key 能让**正确的组件实例和 DOM 状态跟随数据**移动，而非被错误复用；例如输入框内容、内部状态会随数据正确迁移。反之，用 index 当 key 时，前方插入可能导致**旧实例被错误复用**，引发输入错乱。注意：**改变 key 通常表示新身份**，会导致组件**卸载并重新创建**，可借此刻意重置状态。

## 【问题】
列表中重复 key 或主动改变 key 会发生什么？

## 【回答】
- **重复 key**：会破坏 key→节点的身份映射，产生**警告或错误复用**，组件状态与数据对不上；
- **主动改变 key**：等同于告诉框架这是**新身份**，旧组件会被**卸载并重新创建**，常用于**刻意重置组件状态**（如表单重置）。

所以 key 既是复用依据，也是重置开关；生产环境应使用**后端返回的稳定唯一 id** 作为 key。

## 【问题】
Diff 算法为什么用"工程假设"而不是求理论最少 DOM 操作？

## 【回答】
完整树的**编辑距离计算复杂度高**，框架转而基于工程假设：**只比较同层、类型不同则替换、同类型节点复用并 patch 属性与子节点**；Vue3 对带 key 的子序列还会建立 **key 到新索引的映射**识别可复用节点，并通过**最长递增子序列（LIS）**减少移动次数。目标是**足够好的工程更新**，而不是理论上的最少 DOM 操作——在真实场景中已能大幅减少 DOM 改动。

## 【问题】
面试时怎么答「虚拟 DOM / Diff / key」？（基础版）

## 【回答】
VDOM 是 **UI 的中间表示（JS 对象描述界面）**，Diff 在**同层比较**新旧 VNode，并通过**类型和 key** 决定复用、更新或替换。`key` 提供**稳定身份**，影响 DOM 移动和组件状态复用，所以 **index 在可重排列表中有风险**。VDOM 的核心价值是**声明式更新和 renderer 抽象**，不是绝对性能最优。一句话：**用 JS 对象模拟 DOM，数据变化时 diff 找出最小差异批量更新，本质是用 JS 计算换 DOM 操作成本。**
