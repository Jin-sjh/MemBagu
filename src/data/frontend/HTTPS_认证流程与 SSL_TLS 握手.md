# HTTPS 原理

## 1. 为什么需要 HTTPS

## 【问题】为什么需要 HTTPS？HTTP 存在哪些安全问题？

## 【回答】
HTTP 存在以下安全问题：
- HTTP 明文传输：数据在传输过程中以明文形式暴露，容易被窃听
- 无法防篡改：传输内容可能被中间人篡改，无法保证数据完整性
- 无法验证身份：无法确认通信对方的真实身份，容易遭受中间人攻击

## 2. HTTPS 是什么

## 【问题】HTTPS 是什么？它解决了什么问题？

## 【回答】
HTTPS（HTTP Secure）是在传输层和应用层中间添加了一层 TLS/SSL 加密层，实现了：
- 加密传输：数据加密，防止窃听
- 完整性校验：防止数据被篡改
- 身份验证：通过数字证书验证服务器身份

注意：SSL 已经被淘汰，现使用 TLS 1.2/1.3。

## 3. HTTPS 的核心技术

### 3.1 对称加密

## 【问题】什么是对称加密？有什么特点？

## 【回答】
对称加密是指加密和解密使用同一个密钥。
- 特点：速度快，分发难，适合大量数据传输
- 缺点：密钥分发困难，如何安全地将密钥传递给对方是个问题

### 3.2 非对称加密

## 【问题】什么是非对称加密？有什么特点？

## 【回答】
非对称加密使用一对密钥：公钥 + 私钥。
- 公钥可以公开，用于加密数据
- 私钥保密，用于解密数据
- 特点：安全性高，运算慢，不适合加密大体积数据

### 3.3 数字证书 + 数字签名

## 【问题】数字证书和数字签名的作用是什么？

## 【回答】
数字证书和数字签名用于：
- 防止伪造服务器：通过 CA 颁发的证书验证服务器身份
- 防止篡改公钥：通过数字签名确保公钥在传输过程中未被篡改

## 4. HTTPS 握手流程（TLS 1.2）2RTT

## 【问题】HTTPS 握手流程是怎样的？（TLS 1.2）

## 【回答】
HTTPS 使用非对称密钥安全协商出对称密钥，后续所有数据使用对称加密高速传输。

TLS 1.2 握手流程（2RTT）：

**步骤 1**：客户端发送 Client Hello
- 支持的 TLS 版本
- 支持的加密套件列表
- 客户端随机数（Client Random）

**步骤 2**：服务端返回 Server Hello
- 确认 TLS 版本
- 选中的加密套件
- 服务端随机数（Server Random）
- 服务器数字证书

**步骤 3**：客户端校验证书
- 验证证书是否过期
- 验证证书是否被吊销
- 验证证书是否由可信 CA 颁发
- 使用 CA 公钥解密数字签名，验证证书完整性

**步骤 4**：客户端生成预主密钥
- 生成预主密钥（Pre-Master Secret）
- 使用服务器公钥加密预主密钥
- 发送给服务端

**步骤 5**：双方各自计算会话密钥
- 客户端和服务端都使用相同的算法
- 基于三个随机数（Client Random、Server Random、Pre-Master Secret）生成相同的会话密钥

**步骤 6**：握手结束，加密通信
- 后续所有数据传输都使用会话密钥进行对称加密

## 5. HTTPS 的危险点

## 【问题】HTTPS 存在哪些安全风险？

## 【回答】
HTTPS 的危险点包括：
- 证书过期、证书泄漏、私钥泄漏
- 老旧 TLS 版本漏洞（如 SSL 3.0、TLS 1.0/1.1 存在已知漏洞）
- 混合内容：使用 HTTPS 加载 HTTP 资源（会被浏览器阻止或警告）

---

## 【问题】
TLS 提供了哪三项安全目标，又有哪些边界？

## 【回答】
- **机密性：旁观者不能直接读取内容**
- **完整性：篡改会被检测**
- **身份认证：客户端可验证服务器控制目标域名的证书链**

但 **TLS 不能替代授权、输入校验、XSS/CSRF 防护**，也不能保证服务器内部没有恶意逻辑。

---

## 【问题】
TLS 握手的大致流程是怎样的？

## 【回答】
流程为 **ClientHello（能力、随机数、SNI 等）→ ServerHello + 证书 + 密钥交换材料 → 客户端验证证书链、域名和有效期 → 双方派生会话密钥 → HTTP 在加密记录中传输**。**非对称密码学适合身份认证和密钥协商，对称加密适合大量数据传输**；CA 体系帮助浏览器把证书公钥与域名身份建立信任链。

---

## 【问题】
TLS 1.3 相比之前有什么改进，又有什么代价？

## 【回答】
**TLS 1.3 简化握手、减少往返并移除不安全旧算法**，但证书验证、加解密、连接建立仍有 CPU 和延迟成本；**0-RTT 等优化有重放风险边界，不能无条件用于非幂等请求**。

---

## 【问题】
面试时怎么答"HTTPS 如何保证安全"？

## 【回答】
**HTTPS = HTTP + TLS**。TLS 通过证书验证服务器身份，通过密钥交换建立会话密钥，再用对称加密保护数据完整性和机密性。**非对称加密主要解决认证/协商，对称加密负责高效传输**。HTTPS 不能直接防 XSS、CSRF 或权限错误。用浏览器 Security/Network、证书链和抓包工具验证协议版本、证书、握手和资源加载。
