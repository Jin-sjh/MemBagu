# 泛型

## 【问题】
什么是泛型？为什么需要它？

## 【回答】
泛型把“**类型**”作为参数传入，让同一段代码在保持**输入输出类型关系**的同时适用于多种具体类型。例如 `function first<T>(items: T[]): T | undefined`。复制多份函数会重复实现；使用 `any` 虽然省事却丢失输入输出关联。泛型在复用和精确性之间取得平衡：实现写一次，调用点通过推断得到具体类型。它不是运行时的类型参数，也不是把所有值变成 `any`。

---

## 【问题】
泛型与 `any` 有什么区别？

## 【回答】
```ts
function identityAny(x: any): any { return x; }
function identity<T>(x: T): T { return x; }
const a = identityAny(1); // any
const b = identity(1);    // number
```

泛型**保留关系**，`any` 则放弃关系和检查。泛型不能自动保证外部数据真实可靠，输入仍需运行时校验。

---

## 【问题】
泛型约束中 `extends` 表示什么？

## 【回答】
编译器根据调用参数推断 `T`，再检查函数体和返回值；可显式指定类型或添加约束：

```ts
function getLength<T extends { length: number }>(value: T): number {
  return value.length;
}
```

`extends` 在泛型中表示**能力约束，不表示类继承**。`T extends keyof U` 等写法可把一个参数限制为另一个类型的键集合。泛型约束应描述实现真正需要的最小能力，过度约束会降低复用性。

---

## 【问题】
泛型适合用在哪些场景？

## 【回答】
- 工具函数：数组转换、缓存、响应式包装、请求封装。
- 组件：Props、事件值和插槽保持关联。
- SDK：请求参数与响应类型成对约束。
- 工厂和类：实例类型与构造参数关联。

复杂泛型若导致诊断难懂、编译缓慢或 API 难用，应退回更简单的显式类型；**类型系统服务于接口理解，不是竞赛**。

---

## 【问题】
常见误区：泛型会在运行时检查类型吗？

## 【回答】
误区包括“泛型会在运行时检查类型”“泛型越多越安全”“extends 一律表示继承”。验证时用不同输入调用泛型函数观察编辑器推断、测试约束外的参数是否报错、用 `tsc --noEmit` 建立类型测试。

---

## 【问题】
面试时怎么答泛型？

## 【回答】
泛型是类型层面的参数化，让同一实现适用于多种类型，同时维护输入输出关系。相比 `any`，泛型不会丢失类型信息；泛型约束用 `extends` 表示调用者必须提供某种能力，不等同于类继承。使用泛型时先明确需要保持的关系，再设置最小约束，并用类型测试验证推断结果。
