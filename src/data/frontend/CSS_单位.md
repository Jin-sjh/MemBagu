# CSS 单位

## 问题 0：rem、em、vw、vh、% 有什么区别？

## 【问题】
rem、em、vw、vh、% 有什么区别？

## 【回答】
1. em：相对单位，相对于父元素字体大小，嵌套会叠加，适合组件局部尺寸。
2. rem：相对单位，相对于根元素 (html) 字体大小，无嵌套问题，适合移动端适配。
3. vw/vh：视口单位，相对于屏幕可视区域宽/高，不受父元素影响，适合全屏布局。
4. %：相对单位，相对于父元素对应属性，常用于流式布局。

## 问题 1：px、em、rem 的区别及使用场景

## 【问题】
px、em、rem 的区别及使用场景

## 【回答】
**区别：**

- px 是固定的像素，一旦设置了就无法因为适应页面大小而变。
- em 和 rem 相对于 px 更加灵活，他们是相对长度，其长度不是固定的，更适应与响应式布局。
- rem 与 em 区别在于 使用 rem 为元素设置大小时，参照的是 HTML 元素的 font-size，而 em 是以自身的 font-size 为参考的。

**使用场景：**

- 对于只需要适配少部分移动设备，且分辨率对页面影响不大的，使用 px 即可。
- 对于需要适配各种移动设备，使用 rem，例如需要适配 iPhone 和 iPad 等分辨率差别比较挺大的设备。

## 问题 2：如何根据设计稿进行移动端适配？

## 【问题】
如何根据设计稿进行移动端适配？

## 【回答】
**适配不同像素密度**

针对不同的像素密度，使用 CSS 媒体查询，选择不同精度的图片，以保证图片不会失真；

**适配不同屏幕大小**

由于不同的屏幕有着不同的逻辑像素大小，所以如果直接使用 px 作为开发单位，会使得开发的页面在某一款手机上可以准确显示，但是在另一款手机上就会失真。为了适配不同屏幕的大小，应按照比例来还原设计稿的内容。

## 问题 4：当下主流的写法是什么？

## 【问题】
当下主流的写法是什么？

## 【回答】
1. 编写<meta> 标签设置 viewport 的内容。width = device - width，让网页宽度等于视窗宽度。
2. 在 CSS 中使用 px
3. 在适当的场景使用 flex 布局 或者配合 vw 进行自适应。
4. 在跨设备类型的时候，使用媒体查询。
5. 在跨设备类型如果交互差异太大的情况下，考虑分开项目开发。

## 【问题】
px 是物理像素吗？em 和 rem 分别参照谁计算？

## 【回答】
**px 是 CSS 像素，不等于物理像素**（受设备像素比 DPR 影响）。**em 相对当前元素的字体大小**，会随嵌套叠加；**rem 相对根元素（html）的字体大小**，无嵌套叠加问题，适合统一设计尺度与无障碍缩放；**vw/vh 相对视口**；百分比参照物由具体属性和布局上下文决定。不要背"px 就是 1 物理像素"。

---

## 【问题】
为什么 height: 100% 有时不生效？

## 【回答】
`height: 100%` 需要**父级有确定高度**才能解析为期望尺寸；若父级高度是 auto（由内容撑开），百分比高度无法参照，于是失效。常见解法是为祖先链显式设置高度，或改用 `flex: 1`、`grid` 等由布局分配高度的方式，而非依赖百分比。

---

## 【问题】
移动端 100vh 为什么会导致页面跳动？svh / lvh / dvh 是什么？

## 【回答】
移动端 `100vh` 可能把动态浏览器 UI（地址栏）也算进去，当地址栏收起/展开时视口高度变化，导致布局跳动。为此引入新单位：**svh（小视口高度）、lvh（大视口高度）、dvh（动态视口高度）**，分别固定取最小、最大或随变化取实时高度，适合按"是否允许变化"选择，避免跳动。

## 【问题】
clamp() 有什么用？

## 【回答】
`clamp(min, preferred, max)` 在给定范围内流式缩放：取值为 **preferred 被夹在 min 与 max 之间**。例如 `font-size: clamp(14px, 2vw, 20px)` 表示字号随视口在 14~20px 间平滑缩放，既保证可读性又避免极端尺寸。它比写多段媒体查询更简洁，适合流式响应式的尺寸控制。
