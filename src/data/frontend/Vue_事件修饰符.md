# Vue 事件修饰符

## 【问题】
事件修饰符（如.native）底层做了哪些处理？

## 【回答】

### 1. 通用事件修饰符（.stop/.prevent/.once 等）

底层本质是**高阶函数包装回调**：在执行用户定义的回调函数前，先执行修饰符对应的逻辑（如阻止冒泡、阻止默认行为、只执行一次），再调用原回调，是对原生事件行为的封装增强。

### 2. .native 修饰符

专门用于给**Vue 组件绑定原生 DOM 事件**，底层核心处理：

- 强制**跳过 Vue 自定义事件的发布订阅机制**；

- 直接获取组件实例对应的**根 DOM 元素**；

- 调用原生 `addEventListener` 给该根元素绑定原生事件，实现直接监听组件 DOM 原生事件的效果。

## 真实业务 / 面试场景（案例补充）

### 场景 1：弹窗内部点击却把弹窗关了
**背景**：点击弹窗里的内容，事件冒泡到遮罩层，触发了关闭逻辑。
**解决**：在内部容器上用 `@click.stop`，阻止冒泡，点内容不会关弹窗；只在遮罩层 `@click` 上关。

### 场景 2：提交按钮防止连点重复提交
**背景**：用户快速连点"提交"，发了多次请求造成重复下单。
**解决**：用 `@click.once`，回调只执行一次；或配合 `.stop`/`.prevent`（`.prevent` 阻止表单默认提交刷新）。

### 场景 3：Vue2 里给组件绑原生事件为什么要用 .native
**背景**：在封装的 `<MyInput @click="...">` 上写 @click，发现不生效（组件只发了自定义 click 事件）。
**解决**：Vue2 用 `@click.native` 才能监听到组件根 DOM 的原生 click；Vue3 已移除 .native，事件默认穿透到根元素（或用 `inheritAttrs`/显式 emits 控制）。
