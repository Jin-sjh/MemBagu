# 设计前端错误监控系统

## 【问题】
设计前端错误监控系统

## 【回答】
系统设计：

1. **捕获前端错误**：通过 `window.onerror`、`Promise.reject` 捕获同步和异步错误。

2. **错误上报**：将错误信息上报至后端服务器，附带堆栈信息、浏览器版本等。

3. **数据存储和分析**：后端存储错误日志，并提供分析工具。

4. **实时告警**：系统可根据错误类型和频率实时发送告警通知。

---

## 真实业务 / 面试场景（案例补充）

### 场景 1：线上白屏了，但本地复现不了
**为什么**：错误只发生在用户真实环境（特定机型/网络），本地没报错。
**解决**：用 `window.onerror` 捕获全局错误、`unhandledrejection` 捕获 Promise 异常，把错误栈 + 浏览器/系统信息上报到监控后端，结合告警（钉钉/企微）第一时间发现。

### 场景 2：压缩后的代码堆栈看不懂
**为什么**：生产构建做了混淆压缩，报错行列号对不上源码。
**解决**：用 SourceMap 把压缩后的堆栈还原成源码位置；上传 SourceMap 到监控平台（注意别泄露到公网）。

### 场景 3：错误量太大，上报把接口打爆
**解决**：做抽样上报（如采样 10%）和去重（同一错误短时间只报一次），结合聚合统计错误率/影响用户数，而不是每条原始错误都落库。
