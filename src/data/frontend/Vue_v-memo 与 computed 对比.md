# v-memo 与 computed 对比

## 【问题】
Vue 中 v-memo 和 computed 的核心区别是什么？

## 【回答】

**computed 缓存的是【数据值】；v-memo 缓存的是【模板子树（VNode 整棵 DOM 片段）】。**

### 1. 作用对象不同

- **computed**：JS 层的**计算属性**，用于**派生、加工数据**，缓存的是计算出来的值。

```js
const fullName = computed(() => firstName.value + lastName.value)
```

依赖变化 → 重新执行 getter 算出新值；依赖不变 → 直接返回旧值。**是对数据的缓存**。

- **v-memo**：模板里的**指令**，作用在 DOM 元素 / 组件上，缓存**一整段模板子树**（元素 + 所有子节点）。

```html
<div v-memo="[valueA, valueB]"> ... </div>
```

依赖数组不变 → **直接跳过这一整块的虚拟 DOM 创建、diff、patch 更新**，子组件也不会走更新流程。**是对渲染结果（VNode 子树）的缓存**。

### 2. 依赖收集方式不同

- **computed**：**自动追踪依赖**。不用手动列依赖，内部自动收集 getter 里用到的响应式变量。
- **v-memo**：**手动写依赖数组** `v-memo="[a, b]"`，Vue 只对比你写的这几个值（浅比较 `Object.is`），**不会自动追踪模板内部变量**。漏写依赖会出 bug。

### 3. 解决的问题完全不同

- **computed**
  - 把模板中的复杂计算抽离，复用派生数据，**避免模板里重复运算**。
  - 保证返回值引用稳定，作为 props 传给子组件时**减少子组件不必要的渲染**（间接优化渲染）。
  - **不会阻止父组件本身重新渲染**。

- **v-memo**
  - **强行跳过一大块模板的 diff 和更新**，哪怕父组件已经触发了重渲染。
  - 典型场景：巨型 `v-for` 列表、很重的子组件、复杂表格行 —— 只在少数字段变化时才重渲染该行。
  - 属于**高级性能优化手段**，绝大多数普通页面根本不需要用。

### 4. 完整示例

```vue
<script setup>
const a = ref(1)
const b = ref(2)
// computed：缓存计算出来的值
const sum = computed(() => a.value + b.value)
</script>

<template>
  <div>
    <p>{{ sum }}</p>
    <!-- v-memo：缓存下面这整棵子树，a、b 不变则内部所有内容不更新 -->
    <div v-memo="[a, b]">
      <HeavyComponent />
      <p>很多复杂 DOM 节点</p>
    </div>
  </div>
</template>
```

### 5. 对比总表

| 特性 | computed | v-memo |
| --- | --- | --- |
| 缓存目标 | 计算出来的**数据值** | 模板子树 **VNode**（DOM 片段） |
| 位置 | script 脚本内 | template 模板标签上（指令） |
| 依赖 | 自动收集 | 手动写依赖数组，浅比较 `Object.is` |
| 效果 | 依赖不变，不重复计算数值 | 依赖不变，直接跳过整段 diff / patch 更新 |
| 主要用途 | 数据派生、格式化、过滤 | 大型子树 / 长列表的渲染性能优化 |
| 使用频率 | 高频，日常必用 | 低频，仅遇到明显卡顿才考虑 |

## 【问题】
使用 v-memo 有哪些容易踩的坑？

## 【回答】

1. **v-memo 不能当变量用**：computed 是**响应式数据**，可以在模板多处引用取值；v-memo 只控制渲染过程，**不产生任何可访问的值**。
2. **漏写依赖导致隐性 bug**：依赖数组写错 / 少写，会出现**数据变了但页面不更新**的问题，且这类 bug 很难定位。computed 自动追踪依赖，不容易漏。
3. **不要滥用**：Vue 官方提醒，diff 本身开销并不大，只有在遇到**非常重的子树**且成为渲染瓶颈时才上 v-memo。普通页面使用它只会增加维护成本。
4. **只做浅比较**：依赖数组用 `Object.is` 比较，对象 / 数组类型依赖需要保证引用变化才能正确触发更新。

## 【问题】
为什么 computed 能减少子组件的不必要渲染，却不能阻止父组件自身重新渲染？

## 【回答】

- computed 缓存的是**值**。依赖不变时多次读取返回**同一个引用**，子组件收到的 props 引用不变，因此子组件可以跳过更新 —— 这是**通过稳定 props 引用间接减少子组件渲染**。
- 但父组件的渲染函数是否执行，取决于父组件自身依赖的响应式数据是否变化，与 computed 是否被缓存无关，所以 **computed 无法阻止父组件本身重新渲染**。
- 要在父组件重渲染时**仍然跳过某段子树的 diff / patch**，只能靠 **v-memo**（或 `v-once`、组件级 `shouldUpdate` 类手段）—— 这是两者最本质的分工差异。
