# DNS 解析的过程

## 【问题】
请详细描述 DNS 解析的完整过程。

## 【回答】
DNS 解析过程分为以下五个步骤：

### 1. 浏览器缓存
首先查看浏览器的 DNS 缓存中是否有该域名的解析记录。

### 2. 操作系统缓存
如果浏览器没有缓存，再查看操作系统的 DNS 缓存。

### 3. 本地 DNS 服务器查询
如果操作系统缓存中也没有，查询配置的本地 DNS 服务器。

### 4. 递归查询
本地 DNS 服务器会进行递归查询，具体包括以下三个子步骤：

- **根域名服务器**：本地 DNS 服务器首先向根域名服务器查询，根服务器知道顶级域（TLD）服务器的地址。

- **TLD 服务器**：根域名服务器返回 TLD 服务器的地址，本地 DNS 服务器向 TLD 服务器查询（如 `.com`、`.cn`）。

- **权威 DNS 服务器**：TLD 服务器返回最终域名的权威 DNS 服务器地址，本地 DNS 服务器向权威 DNS 服务器查询该域名的 IP 地址。

### 5. 返回结果
解析完成后，本地 DNS 服务器将结果返回给客户端。

## 真实业务 / 面试场景（案例补充）

### 场景 1：二次访问同一域名"秒开"，没走网络解析
**为什么**：浏览器缓存、操作系统缓存、本地 DNS 缓存逐层命中，前几步就直接返回 IP，无需递归查询。
**应用**：这也是为什么首次访问慢、再次访问快——缓存生效了。

### 场景 2：改了域名解析，过几分钟还没生效
**为什么**：DNS 有 TTL 缓存，递归服务器和本地都会暂存结果。
**解决**：等 TTL 过期；或清本地缓存（`ipconfig /flushdns` / `systemd-resolve --flush-caches`），必要时换公共 DNS。

### 场景 3：域名被解析到奇怪 IP（疑似劫持）
**为什么**：本地 DNS 或被运营商篡改返回错误 IP。
**解决**：改用 DoH（DNS over HTTPS）/ DoT 加密查询防篡改。

### 场景 4：面试——递归查询和迭代查询区别
**要点**：递归是"客户端只问一次，本地 DNS 替你一层层问到底"；迭代是"服务器只告诉你下一步该问谁，你自己接着问"。浏览器/客户端走递归，服务器之间走迭代。
