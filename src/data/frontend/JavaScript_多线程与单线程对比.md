# 多线程相关问题

## 【问题】
多线程比单线程的优势，劣势？

## 【回答】

### 优势
提高程序的运行效率，可以充分利用多核处理器的资源，同时处理多个任务，加快程序的执行速度。

### 劣势
1. **数据竞争访问问题**：存在多线程数据竞争访问的问题，需要通过锁机制来保证线程安全，增加了加锁的开销
2. **死锁风险**：还会有死锁的风险
3. **资源消耗**：多线程会消耗更多系统资源，如 CPU 和内存，因为每个线程都需要占用一定的内存和处理时间

---

## 【问题】
多线程是不是越多越好，太多会有什么问题？

## 【回答】

多线程不一定越多越好，过多的线程可能会导致一些问题。

- **切换开销**：线程的创建和切换会消耗系统资源，包括内存和 CPU。如果创建太多线程，会占用大量的系统资源，导致系统负载过高，某个线程崩溃后，可能会导致进程崩溃。

- **死锁的问题**：过多的线程可能会导致竞争条件和死锁。竞争条件指的是多个线程同时访问和修改共享资源，如果没有合适的同步机制，可能会导致数据不一致或错误的结果。而死锁则是指多个线程相互等待对方释放资源，导致程序无法继续执行。

## 真实业务 / 面试场景（案例补充）

### 场景 1：大数据排序不卡页面
**背景**：前端要排序/解析 10 万条数据，放主线程会卡死 UI。
**解决**：用 Web Worker 把计算移到后台线程，算完 postMessage 回主线程，页面仍可交互。这正是"多线程"在 JS 里的实际应用。

### 场景 2：开了太多 Worker 反而更慢
**为什么**：线程有创建、切换、内存开销；如果任务本身很小，频繁建 Worker 的代价超过并行收益，还会吃光内存。
**解决**：用线程池复用固定数量的 Worker，按任务量调度，而不是来一个任务开一个线程。

### 场景 3：面试——JS 是单线程，为什么还要讲多线程
**要点**：JS 主线程单线程是为了避免 DOM 操作的竞态；但浏览器/Node 用多线程（网络、解码、Worker）协作，加上"多线程 vs 单线程"的优劣（效率 vs 复杂度/死锁）是通用计算机基础题。
