## 【问题】与 HTTPS 相比，HTTP 有什么缺点？

## 【回答】
HTTP 的缺点如下：

（1）通信使用明文，不加密，内容可能被窃听，也就是被抓包分析。

（2）不验证通信方身份，可能遭到伪装。

（3）无法验证报文完整性，可能被篡改。

HTTPS 就是 HTTP+加密处理（一般是 SSL 安全通信线路）+认证+完整性保护。

## 【问题】如何优化 HTTP 请求？

## 【回答】
利用负载均衡优化和加速 HTTP 应用请求；利用 HTTP 缓存来优化网站请求。

## 【问题】HTTP 协议有哪些特征？

## 【回答】
支持客户端/服务器模式，简单快速，灵活，无连接，无状态。

---

## 【问题】HTTP 1.1 版本的新特性有哪些？

## 【回答】
新特性如下所示：

（1）默认持久连接，节省通信量，只要客户端/服务端中任意一端没有明确指出断开 TCP 连接，就一直保持连接，可以多次发送 HTTP 请求。

（2）管线化，客户端可以同时发出多个 HTTP 请求，而不用一个个等待响应。

（3）断点续传原理。

## 真实业务 / 面试场景（案例补充）

### 场景 1：页面被运营商插入广告
**背景**：网站用 HTTP，用户访问时莫名多出运营商广告条。
**为什么**：HTTP 明文传输，中间节点（路由器/运营商）能看见并篡改内容。
**解决**：全站升级 HTTPS，报文加密 + 完整性校验，中间人无法篡改。

### 场景 2：HTTP/1.0 下每个请求都重新建连，很慢
**为什么**：HTTP 早期"无连接"，每次请求新建 TCP 再断开，握手开销大。
**解决**：HTTP/1.1 默认 Keep-Alive 持久连接、可管线化（pipelining）复用；但管线化仍有队头阻塞，故进一步演进到 HTTP/2 多路复用。

### 场景 3：面试——HTTP 有哪些特征、有什么缺点
**要点**：特征：C/S 模式、简单快速、灵活、无连接、无状态。缺点：明文（被窃听）、不验证身份（被伪装）、无法验证完整性（被篡改）——HTTPS 正是针对这三点补上加密、认证、完整性保护。

## 【问题】
HTTP 的"无状态"和"长连接"是一回事吗？

## 【回答】
不是同一层概念。**HTTP 无状态表示协议本身不自动记住上一次请求的应用会话**，但不代表服务器不能通过 Cookie、Session、Token 或数据库保存状态。而**HTTP 长连接是复用已有传输连接的策略**，TCP 长连接只是底层连接未关闭，二者不是同一层概念。

## 【问题】
GET 和 POST 的核心区别是什么，能说 POST 更安全吗？

## 【回答】
GET 通常用于获取资源并应尽量保持安全/幂等语义，POST 常用于提交或触发处理；核心差异在**语义、缓存、幂等和载荷使用习惯**。**规范并不等于"GET 永远没有 body"或"POST 天然安全"**，安全取决于 TLS、认证、授权、CSRF、输入处理等整体设计，不能简单说 POST 更安全。

## 【问题】
HTTP 状态码如何按类别理解？

## 【回答】
- **2xx：成功**
- **3xx：重定向或缓存相关**
- **4xx：请求或权限问题**，如 **401 未完成认证**、**403 已识别但拒绝访问**
- **5xx：服务器或上游问题**，如 **502 上游响应无效**、**503 暂时无法服务**

状态码要按请求是否成功、客户端问题还是服务端/上游问题理解。

## 【问题】
HTTP Header 起什么作用？

## 【回答】
**Content-Type 描述消息内容媒体类型**；Header 承载**缓存、认证、协商、来源和传输控制**元数据。**Keep-Alive 让连接可复用，但不保证请求永远不关闭**。用 Network 面板检查方法、Header、body、状态码和连接复用，并结合 RFC 而不是浏览器习惯作绝对判断。
