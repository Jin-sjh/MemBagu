# 为什么并发执行线程要加锁？

## 【问题】
为什么并发执行线程要加锁？

## 【回答】
并发执行线程需要加锁主要是为了保护共享数据，防止出现"竞态条件"。

"竞态条件"是指当多个线程同时访问和操作同一块数据时，最终结果依赖于线程的执行顺序，这可能导致数据的不一致性。

通过加锁，我们可以确保在任何时刻只有一个线程能够访问共享数据，从而避免"竞态条件"，确保数据的一致性和完整性。

## 真实业务 / 面试场景（案例补充）

### 场景 1：Web Worker 用 SharedArrayBuffer 做全局计数器
**背景**：主线程 + 多个 Worker 同时 `count++`，结果总比预期小。
**为什么**：`count++` 不是原子操作，它读出 → 加一 → 写回三步，多线程交错执行时互相覆盖（竞态条件）。
**解决**：用 `Atomics.add(sharedArray, 0, 1)` 保证这一步原子完成；或加 `Mutex` 锁。这就是"并发要加锁"的典型场景。

### 场景 2：Node.js 多进程集群写同一日志文件
**背景**：`cluster` 模式 4 个 worker 同时 `fs.appendFile`，日志偶尔丢失 / 错乱。
**为什么**：文件 IO 不是原子的，交错写入会互相覆盖。
**解决**：用消息队列把写操作收敛到单一进程，或加文件锁（如 `fcntl`）。

### 场景 3：面试反转题——JS 主线程不是单线程吗，为什么还要锁？
**回答要点**：JS 主线程确实单线程，不存在主线程内的竞态；但 **Web Worker / SharedArrayBuffer / WebAssembly 多线程 / Node 集群** 是多线的，这些场景下共享内存就需要加锁（Atomics / Mutex）。
