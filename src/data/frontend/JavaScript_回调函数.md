# 回调函数

## 【问题】
什么是回调函数？

## 【回答】
回调函数就是一个通过函数指针调用的函数。如果把函数的指针（地址）作为参数传递给另一个函数，当这个指针用来调用其所指向的函数时，我们就说这是回调函数。回调函数不是由该函数的执行方直接调用的，而是在特定的事件或条件发生时由另一方调用的，用于对该事件或条件进行响应。

---

## 真实业务 / 面试场景（案例补充）

### 场景 1：回调地狱（callback hell）
**背景**：先登录拿 token，再拿 token 请求用户信息，再拿 userId 请求订单，层层嵌套。
**为什么**：每一步都依赖上一步结果，用回调只能往里套，可读性差、错误处理难。
**演进**：用 `Promise` 的 `.then` 链式扁平化，再用 `async/await` 写成同步风格，从根本上摆脱回调嵌套。

### 场景 2：回调"不调用 / 多次调用"的坑
**背景**：封装一个 `request(url, cb)`，网络异常时没调 `cb` → UI 永远转圈；或重试逻辑导致 `cb` 被调两次 → 弹窗弹两次。
**为什么**：回调是"约定"，缺乏约束，调用方容易漏调、多调。
**解决**：统一用 Promise 封装（要么 resolve 要么 reject，且只触发一次），避免裸回调。

### 场景 3：事件监听就是回调
**背景**：`button.addEventListener('click', handler)`，点击时由浏览器"另一方"调用 `handler`。这正符合回调定义——函数不是你直接调，而是特定事件发生时由系统 / 库回调你。
