# HTTP 协议演进

## 1. HTTP 各版本差异

### 【问题】
HTTP 各版本（1.0、1.1、2.0、3.0）的主要差异是什么？

### 【回答】

#### HTTP/1.0
- 支持图片、文件、编码等多媒体
- 默认短连接
- 每次连接TCP三挥四握
- 无强缓存/协商缓存分层

#### HTTP/1.1
- **持久连接（Keep-Alive）**：减少握手开销
- **管道化**：同一连接发送多个请求，队头堵塞存在
- **Host头**：单一服务器部署多个域名
- 完善强缓存和协商缓存
- 支持断点续传、大文件分片下载
- **存在的问题**：
  - TCP队头阻塞
  - 浏览器并发限制：单一域名6-8个TCP连接
  - 头部冗余：重复传输，开销大

#### HTTP/2
- 使用**二进制协议**，解析更快
- **多路复用**：一TCP并发多个请求；请求唯一stream；乱序发送、有序组装
- 解决应用层队头阻塞，TCP层队头阻塞仍存在（一流丢包，整个重传）
- **头部压缩**：HPACK，重复头部仅传索引
- 服务器主动推动未请求但可能需要的资源
- 客户端可标注流优先级
- **仍存在的问题**：
  - TCP层队头阻塞
  - 网络切换连接迁移差

#### HTTP/3
- 基于**UDP和QUIC协议**
- **快速建立连接**：首次 1RTT（QUIC+TLS 合并），二次 0-RTT
- **实现连接迁移**：quic连接由 Connection ID 标识，网络切换不中断
- **QPACK头部压缩**，压缩更高效
- **强制TLS1.3**，默认加密，无明文传输，安全性更高

#### 版本演进总结
- **1.0→1.1**：解决短连接开销，引入持久连接、缓存、Host 头，成为互联网基石。
- **1.1→2**：解决应用层队头阻塞 + 头部冗余，用二进制 + 多路复用 + HPACK，性能飞跃。
- **2→3**：解决TCP 层队头阻塞 + 连接迁移，基于 QUIC 彻底重构传输层，适配移动网络与高并发场景。

## 4. HTTPS 和 HTTP 的区别，HTTPS 是如何保证安全的

### 【问题】
HTTPS 和 HTTP 的区别，HTTPS 是如何保证安全的

### 【回答】

**HTTP：**
- 数据是明文传输的，容易被中间人（如黑客）窃听或篡改。

**HTTPS：**
- **加密**：使用 SSL/TLS 协议对传输的数据进行加密，确保数据在传输过程中的安全性。
- **身份验证**：使用 SSL/TLS 证书对服务器进行身份验证，防止假冒网站。
- **完整性校验**：通过数据摘要（哈希算法）来保证数据在传输过程中不被篡改。

## 3. HTTP/2 解决了什么问题，仍然解决不了的问题，HTTP/3+UDP 如何解决

### 【问题】
HTTP/2 解决了什么问题，仍然解决不了的问题，HTTP/3+UDP 如何解决

### 【回答】

**HTTP/2 解决的问题：**
- 解决了队头阻塞：通过多路复用，一个连接可以并发传输多个请求和响应。
- 头部压缩：减少了数据包头部的冗余数据，提高了带宽利用率。
- TCP 连接复用：减少了大量的 TCP 连接的建立和拆除开销。

**HTTP/2 无法解决的问题：**
- TCP 的固有问题：虽然解决了队头阻塞，但由于 TCP 仍然基于单个连接，存在 TCP 队头阻塞问题，特别是在高延迟和丢包场景下。
- 连接建立时的延迟：TCP 握手依然存在延迟。

**HTTP/3 + UDP：**
- UDP 没有 TCP 的队头阻塞问题，因此通过使用 QUIC 协议实现的 HTTP/3 能避免 TCP 连接中的队头阻塞。
- 多路复用：QUIC 协议允许多个流在一个 UDP 连接中并行传输，解决了 TCP 连接中的队头阻塞问题。
- 更低的连接延迟：QUIC 通过 0-RTT 连接重用，减少了连接建立的延迟。
- 更好的移动网络支持：由于 UDP 是无连接的，适合移动网络中频繁切换网络的情况。
