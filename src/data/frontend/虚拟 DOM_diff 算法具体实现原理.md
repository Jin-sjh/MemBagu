# 虚拟 DOM diff 算法具体实现原理

## 【问题】
虚拟 DOM diff 算法具体实现原理

## 【回答】

### 虚拟 DOM
虚拟 DOM 是 React 等库用来高效更新视图的技术。其基本思路是将实际的 DOM 树与虚拟 DOM 树进行比较，找到差异并进行最小的更新。

### diff 算法

1. **比较节点类型**：如果不同，直接替换。

2. **比较节点的属性和文本内容**。

3. **比较子节点**，通过递归比较。

4. **使用双指针**（同时遍历旧树和新树）来减少计算量。

## 真实业务 / 面试场景（案例补充）

### 场景 1：面试高频——为什么列表要写 key
**背景**：`v-for` 渲染列表时不写 key，或用 index 当 key，遇到"增删/排序"时界面错乱。
**为什么**：diff 用 key 识别"哪些节点是同一个"，有相同的 key 就复用 DOM（只更新内容）；没有稳定 key 就会错误复用、导致状态串台。
**解决**：用数据唯一 id 作 key，不要用数组下标。

### 场景 2：用 index 当 key 的坑
**背景**：列表反转/删除中间项时，用 index 作 key 会让元素"位置没变但内容错位"，输入框内容跟着错位。
**为什么**：index 在增删后会重新编号，key 不再稳定，diff 误以为还是原节点，复用出错。

### 场景 3：diff 为什么只同层比较、不跨层
**为什么**：跨层移动节点（如把子节点移到别的父级）在实际开发中极少，且跨层比对的复杂度是 O(n³)，成本不可接受。
**解决**：框架约定"同层比较 + 双指针"，把复杂度降到 O(n)，用可接受的性能换取绝大多数场景的正确更新。
