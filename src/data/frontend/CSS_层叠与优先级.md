# CSS 层叠与优先级

---

## 问题 1：CSS 的三种引入方式？

## 【问题】
CSS 的三种引入方式？

## 【回答】
1. 行内样式：写在 HTML 元素的 `style` 属性里。

2. 内部样式表：在 HTML 文档的 `<style>` 标签中定义。

3. 外部样式表：单独写在 `.css` 文件中，通过 `<link>` 引入。

---

## 问题 2：浏览器如何决定某个元素最终样式？

## 【问题】
浏览器如何决定某个元素最终样式？

## 【回答】
浏览器依据 **层叠（Cascade）** 机制计算最终样式：先收集所有样式，再按 **权重（Specificity）** 判定优先级（ID > 类 / 伪类 > 元素 / 伪元素）；权重相同时，按 **源码顺序（Source Order）**，后定义的覆盖先定义的；行内样式权重高于普通规则，`!important` 优先级最高。

---

## 问题 3：什么是样式冲突？谁赢？

## 【问题】
什么是样式冲突？谁赢？

## 【回答】
样式冲突是多个 CSS 规则同时作用于同一元素的同一属性时产生的样式冲突。解决规则为：**权重（Specificity）高**的规则胜出，权重顺序为 `!important` > 行内样式 > ID 选择器 > 类 / 伪类 / 属性选择器 > 元素 / 伪元素选择器；**权重相同时，后定义的（源码顺序）样式赢**，核心是 CSS 层叠机制。

## 真实业务 / 面试场景（案例补充）

### 场景 1：设计师改的按钮样式死活不生效
**背景**：组件库自带 `.ant-btn { color: #fff }`（类选择器权重 0,1,0），你在业务代码里写 `.btn-submit { color: #333 }`，发现不生效。
**为什么**：两条都是类选择器，权重相同，谁后加载谁赢；但组件库样式通常在你之前引入，所以你的规则"先定义"反而被覆盖，甚至被组件库的 ID / 内联样式（权重更高）直接压住。
**排查 / 解决**：打开 DevTools → Elements → Styles，看哪条被划掉（strike-through），被划掉的就是被更高优先级或后加载的规则覆盖。临时兜底用 `color: #333 !important`（最高优先级，但会污染，慎用），根治是提升选择器权重（如 `div.btn-submit` 或加业务命名空间）或调整样式引入顺序。

### 场景 2：面试反问"为什么我加了 !important 还是被覆盖？"
**回答要点**：`!important` 之间也有权重比较——多个 `!important` 时仍按具体性 + 源码顺序决胜负；且**行内样式的 `!important` 权重高于外部样式表的 `!important`**。所以 `style="color:red!important"` 会压住样式表里的 `.x { color:blue!important }`。

### 场景 3：全局重置（reset.css）与业务样式顺序
**背景**：在 `reset.css` 之后引入业务 `app.css`，业务样式天然"后定义"从而覆盖 reset，这正是层叠"源码顺序"规则的日常应用；反之若把 reset 放最后，你写的样式都会被清零。

## 【问题】
CSS 层叠（cascade）判断最终样式的顺序是怎样的？

## 【回答】
判断顺序**不是只看"权重"**，而是依次比较：
1. **来源与重要性（origin/importance）**：如作者样式、用户样式、浏览器默认，以及 `!important` 所在的重要性层级；
2. **层叠层（cascade layer / @layer）**；
3. **选择器优先级（specificity）**：可用 (ID, 类, 元素) 三元组理解；
4. **源码顺序（source order）**：相同条件下**后出现的声明生效**。

注意跨位权重**不能用单纯十进制比较**（如 1 个 ID 永远大于任意多个类），且 `!important` 进入更高重要性层级而非"无限大"。

## 【问题】
CSS 的继承机制与 inherit / initial / unset / revert 等全局值是什么？

## 【回答】
**继承**指属性未显式指定时，从父元素获取计算值；并非所有属性都继承。全局值关键字：
- **inherit**：强制取父元素的计算值；
- **initial**：取规范的初始值；
- **unset**：对可继承属性等同 inherit，否则等同 initial；
- **revert**：回退到更早层级的浏览器/用户样式。

这些用于精确控制单个属性的取值来源，是比 `!important` 更细粒度的手段。

## 【问题】
@layer（层叠层）有什么作用？

## 【回答】
`@layer` 把团队、组件和覆盖层级**显式化**，让样式覆盖顺序由 layer 声明决定，而非靠选择器权重或引入顺序"打架"。它**降低了选择器权重战争**：低权重选择器放在高层级 layer 中也能覆盖高权重选择器所在的低层级 layer，从而可以写更简洁、语义化的选择器，避免滥用 `!important` 和无限叠加类名。

---

## 【问题】
!important 的优先级是"无限大"吗？

## 【回答】
不是。`!important` 只是把声明送入**更高的重要性层级**，但仍需结合**来源、layer 和重要性**一起比较；同处 `!important` 层级时，依然按 layer、specificity、源码顺序决胜负。**行内样式的 `!important` 高于外部样式表的 `!important`**。因此它应作为最后手段，而非覆盖冲突的常规解法。
