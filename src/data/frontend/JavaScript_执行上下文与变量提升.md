# 执行上下文与变量提升

## 【问题】
什么是执行上下文？有哪几种？

## 【回答】
执行上下文是 JavaScript 执行一段代码时维护的**运行时信息**（规范机制，不是开发者可直接访问的对象），关联当前正在执行的代码、词法环境、变量环境等状态。常见三种：

- **全局执行上下文**：脚本或模块开始执行时建立。
- **函数执行上下文**：每次调用函数时建立，各自有独立的参数和局部绑定。
- **eval 执行上下文**：执行直接 `eval` 代码时涉及，工程中应避免依赖它。

注意它**不等同于 V8 中可直接查看的对象**，浏览器 Call Stack 只是对规范执行过程的可视化近似。

## 【问题】
什么是作用域和作用域链？JavaScript 用的是词法作用域还是动态作用域？

## 【回答】
**作用域**是语言层面的规则，决定某个标识符在哪段源代码中可见；**作用域链**是运行时沿当前环境到外层环境逐级查找标识符形成的链。

JavaScript 使用**词法作用域（静态作用域）**：标识符的查找由**代码嵌套位置决定**，而不是由函数最终在哪里调用决定。例如内部函数查找外层变量时，先查自己的环境，再查外层，与调用位置无关。一句话：作用域决定"账本能看到哪些变量"，作用域链决定运行时怎么找。

## 【问题】
var、let、const 有什么区别？

## 【回答】
三者都参与**声明实例化**，但初始化时机与作用域不同：

- **var**：函数/全局作用域；声明前已初始化为 `undefined`；同函数作用域通常允许重复声明；可重新赋值。
- **let**：块级作用域；声明前处于 **TDZ**，访问抛 `ReferenceError`；同块不允许重复声明；可重新赋值。
- **const**：块级作用域；同样 TDZ；同块不允许重复声明；**不可重新绑定**（但对象内部属性仍可修改）。

示例：
```javascript
console.log(a); // undefined
var a = 1;
console.log(b); // ReferenceError
let b = 2;
```

## 【问题】
什么是 TDZ（暂时性死区）？为什么 let/const 声明前访问会报错？

## 【回答】
TDZ 是从进入绑定所在作用域、到执行到该声明初始化位置之前的时间区间。在此期间读取、赋值或某些形式的访问会抛 **`ReferenceError`**。

存在原因：若 `let` 像 `var` 一样声明前返回 `undefined`，拼写错误或错误的执行顺序会被静默掩盖；**TDZ 把问题暴露在更靠近错误源的位置**，也保证同一块内绑定语义一致。

注意它通常是**运行时访问点抛出的 `ReferenceError`，不是编译错误**；访问未声明标识符也会抛 `ReferenceError`，但两者原因不同。

## 【问题】
函数声明和函数表达式的提升有什么区别？

## 【回答】
**函数声明**会在相应环境初始化为函数对象，因此可在声明前调用：
```javascript
sayHi(); // 可执行
function sayHi() {}
```
**函数表达式**先按变量声明处理：`var` 绑定初始为 `undefined`，赋值执行后才变成函数对象，所以声明前调用会得到 `TypeError`：
```javascript
run(); // TypeError: run is not a function
var run = function () {};
```
用 `let`/`const` 保存函数表达式时，声明前处于 TDZ。工程中应避免依赖"块中函数声明是否提升"的边缘行为，改用明确 `const fn = () => {}`。

## 【问题】
let/const 到底有没有变量提升？

## 【回答】
**有声明实例化，但不能简单等同于 var 提升。** 更准确的说法：三者都参与声明实例化，但初始化语义不同——函数声明通常直接得到函数对象，`var` 得到 `undefined`，而 `let`/`const` 先创建未初始化绑定（处于 TDZ），所以声明前不可访问。

因此不能说"let 也提升了"就认为声明前可用，只能说**声明在执行前被登记，但值尚未准备好**。

## 【问题】
作用域链和原型链有什么区别？

## 【回答】
二者是**不同机制**：

- **作用域链**：用于查找**变量名/标识符绑定**，基于词法作用域，由函数嵌套关系形成，从当前局部作用域逐层向外直到全局作用域。
- **原型链**：用于查找**对象的属性/方法**，基于对象的 `[[Prototype]]` 引用形成继承链，从实例沿原型向上直到 `Object.prototype`/`null`。

一句话：**作用域链管变量访问，原型链管对象属性与方法的继承**，底层结构和作用场景完全不同。

## 【问题】
变量提升到底是什么？为什么说"代码被移动到顶部"是错误理解？

## 【回答】
正确理解：声明在执行前被**实例化/登记**，但初始化和值的产生仍遵循各自语义（`var` 初始化为 `undefined`、`let` 处于 TDZ、函数声明得到函数对象）。错误理解是把提升当成"代码文本物理移动到顶部"。

相关高频误区：
- 认为 `const` 让对象不可变（实际只禁止绑定重指向，对象内部仍可改）；
- 认为 TDZ 是编译错误（实际是运行时访问点抛 `ReferenceError`）；
- 认为作用域由调用者决定（JavaScript 普通函数使用词法作用域）。
