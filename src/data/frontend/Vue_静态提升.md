# 静态提升

## 【问题】
什么是静态提升（hoistStatic）？

## 【回答】
**静态提升是 Vue 3 compiler 在模板编译阶段做的一种优化**：把模板中**不会变化的静态节点**在编译阶段提取出来，生成一次 VNode 常量，后续渲染直接复用。

具体做了四件事：

1. 分析模板 **AST**；
2. 找出**完全静态的节点**；
3. 将其转换成 **hoisted 常量**；
4. render 执行时**直接引用该常量**。

例如模板：

```html
<div>
  <h1>Hello</h1>
  <p>{{ message }}</p>
</div>
```

编译结果大致为：

```js
const _hoisted_1 = createVNode('h1', null, 'Hello')

function render() {
  return createVNode('div', null, [
    _hoisted_1,
    createVNode('p', null, message.value)
  ])
}
```

`_hoisted_1` 只在初始化时创建一次；如果没有静态提升，它会在**每次 render 执行时被重新创建**。

## 【问题】
静态提升解决什么问题？它优化的是哪部分成本？

## 【回答】
核心是**减少重复创建 VNode 的开销**。

- 静态提升主要优化的是 **JavaScript 执行成本**，而不是 **DOM 操作成本**——因为静态节点本来就不会更新 DOM，每次重新创建它们的 VNode 属于**纯浪费**。
- 静态提升**不负责减少 diff 的比较量**，减少比较是 **patchFlag** 的工作。

## 【问题】
静态提升的编译流程是怎样的？

## 【回答】
1. **解析（parse）**：把模板解析成 **AST**，例如 `div` 下挂 `h1`（"Hello"）与 `p`（`{{ msg }}`）。
2. **静态分析**：判断节点是否**依赖动态数据**。
3. **提升（hoist）**：对静态节点生成 `const _hoisted_1 = createVNode(...)`。
4. **render 复用**：render 函数体内**直接引用** `_hoisted_1`，而不是每次重新 `createVNode`。

```js
// 未提升：每次调用 render 都创建一次
function render() {
  return createVNode('div')
}

// 提升后：只创建一次
const _hoisted_1 = createVNode('div')
function render() {
  return _hoisted_1
}
```

## 【问题】
Vue 编译器依据什么判断一个节点是静态的（static）？

## 【回答】
判断标准是：**该节点是否依赖响应式数据**，而不是"页面上看起来会不会变"。

节点被判定为**静态节点**，意味着它没有：

- **插值**（`{{ }}`）
- **动态属性 / class 绑定**（`:class`、`:style` 等）
- **事件绑定**
- **指令**（`v-if`、`v-for` 等）

```html
<!-- 静态：static = true -->
<div>公司名称</div>

<!-- 动态：static = false -->
<div>{{ company }}</div>
```

注意：即使 `company` **一年都不变**，它依然是**动态节点**——因为**编译器无法预知未来**，只要数据来自响应式系统，就必须按动态处理。

## 【问题】
静态提升和 patchFlag 有什么区别？

## 【回答】
两者解决的是**不同环节**的问题：

- **静态提升**：解决"**不创建**"。静态节点直接复用已有的 VNode 常量。
- **patchFlag**：解决"**创建了，但精准比较**"。例如 `<div :class="cls">hello</div>` 这个节点必须创建，但 Vue 知道**只有 class 会变**，于是打上 `patchFlag = CLASS`，更新时**只比较 class**。

| 优化 | 解决的问题 |
| - | - |
| 静态提升 | 少创建 VNode |
| patchFlag | 少比较 VNode |
| 事件缓存 | 少创建函数 |
| Block Tree | 少遍历节点 |

## 【问题】
静态提升之后，如果变量发生变化怎么办？为什么不把所有节点都提升？

## 【回答】
**静态提升只针对完全不依赖响应式数据的节点**，所以不会出现"提升了但数据变了"的情况。凡是包含**插值、动态属性、指令**的节点**都不会被提升**。

这也是为什么不能全部提升：有些节点只是**现在**不变，但**未来可能变化**，例如：

```html
<div :class="userClass"></div>
```

如果错误地把它提升成常量，**响应式就会失效**。所以 Vue 采用**编译器静态分析**来决定提升范围。

## 【问题】
静态提升和"缓存"有什么区别？

## 【回答】
**缓存**通常针对**函数结果或者计算结果**；**静态提升**针对的是 **VNode 结构**。

例如：

```js
const vnode = createVNode()
```

静态提升"提"出来、被复用的，就是**这个 VNode 对象本身**。

## 【问题】
静态节点是不是永远不会参与 patch？

## 【回答】
**不是绝对的。**

Vue 会通过静态标记**减少**更新路径，但在某些特殊情况下静态节点**仍然可能参与处理**，例如：

- **组件卸载、挂载**
- **key 变化**

## 【问题】
静态提升在什么场景下收益明显？

## 【回答】
**静态节点越多，静态提升的收益越明显**。

典型场景：

- **企业后台管理系统**：`header`（logo、menu）与 `footer`（版权所有）长期不变，只有中间的表格数据在变，静态提升可以减少这些结构的重复创建。
- **组件库、营销页面**：静态内容占比高的页面，收益通常比较明显。

用理论数值感受一下：假设页面有 10000 个节点、其中 9000 个静态，没有优化时每次更新要**创建 10000 个 VNode**，有静态提升后只需**创建 1000 个动态 VNode**，理论上减少约 **90% 的 VNode 创建成本**。

但**实际不会这么理想**，因为还要考虑 **diff 成本、JS 执行、浏览器布局、数据复杂度**。

## 【问题】
其他框架是怎么做同类优化的？（React / Svelte 对比）

## 【回答】
- **React**：没有类似的模板编译层，主要依靠 **memo**、**useMemo**，以及编译器方向上的 **React Forget**。
- **Svelte**：更激进，**在编译阶段直接生成 DOM 操作代码**。

## 【问题】
大厂面试追问：静态提升、patchFlag、Block Tree 三者分别解决什么问题？为什么需要组合使用？

## 【回答】
- **静态提升 = 减少创建**：静态节点不再重复创建 VNode。
- **patchFlag = 减少比较**：动态节点只需比较发生变化的字段。
- **Block Tree = 减少遍历**：用 **Block** 收集动态子节点（**dynamicChildren**），运行时**无需递归遍历整棵 VNode 树**。

三者组合起来，才构成 Vue 3 对"**创建 → 比较 → 遍历**"三个环节的完整优化闭环。
