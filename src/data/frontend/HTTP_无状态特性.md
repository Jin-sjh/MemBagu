# HTTP 无状态特性

## 什么是 HTTP

## 【问题】
什么是 HTTP？

## 【回答】
HTTP 是客户端和服务器端之间数据传输的格式规范，表示"超文本传输协议"。

---

## 什么是 HTTP 无状态协议

## 【问题】
什么是 HTTP 无状态协议？如何克服 HTTP 无状态协议的缺陷？

## 【回答】
（1）无状态协议对于事务处理没有记忆能力。缺少状态意味着如果后续需要处理，需要前面提供的信息。

（2）克服无状态协议缺陷的办法是通过 cookie 和会话保存信息。

---

## HTTP 到底是不是无状态的

## 【问题】
HTTP 到底是不是无状态的

## 【回答】
HTTP 是无状态的，这意味着每个请求都是独立的，服务器不会在多个请求之间保留关于客户端状态的信息。在每个 HTTP 请求中，服务器不会记住之前的请求或会话状态，因此每个请求都是相互独立的。

虽然 HTTP 本身是无状态的，但可以通过一些机制来实现状态保持，其中最常见的方式是使用 Cookie 和 Session 来跟踪用户状态。通过在客户端存储会话信息或状态信息，服务器可以识别和跟踪特定用户的状态，以提供一定程度的状态保持功能。

## 真实业务 / 面试场景（案例补充）

### 场景 1：购物车加了一件商品，刷新后没了
**为什么**：HTTP 无状态，每次请求都"不记得"上一次，服务器不知道这是同一个用户的连续操作。
**解决**：用 Cookie/Session 维持状态——登录后服务器下发 sessionId 存 Cookie，后续请求自动带上，服务器据此识别同一用户。

### 场景 2：为什么无状态反而是优点
**要点**：无状态让每个请求相互独立，服务器不用维护连接状态，易于横向扩展（加机器就能扛更多请求），这是 REST 架构推崇无状态的原因。

### 场景 3：面试——HTTP 到底是不是无状态的
**要点**：HTTP 协议本身无状态；但通过 Cookie、Session、Token 等机制可以在应用层"模拟"出状态保持，二者不矛盾。
