# 基础类型系统

## 【问题】
什么是 TypeScript？它和 JavaScript 是什么关系？

## 【回答】
TypeScript 是 JavaScript 的**静态类型检查与编译工具链**：开发阶段根据类型信息发现一部分错误，最终仍需**编译成 JavaScript 在运行时执行**。它不是运行时类型系统，也不能保证所有用户输入、网络数据和第三方代码在运行时可靠。本质是用静态类型描述值的形状和关系，在构建前提供反馈。

---

## 【问题】
TypeScript 的类型检查发生在什么时候？类型会被保留到运行时吗？

## 【回答】
TypeScript 编译器会解析源码，建立 AST、符号表和类型关系，执行类型检查后再输出目标 JavaScript；**多数类型信息会被擦除**。例如 `function greet(name: string): string` 编译后不会在运行时检查 `name` 是否为字符串。**普通类型标注通常会被擦除**，不能自动生成运行时校验。对外部数据必须使用 schema validator、类型守卫或运行时校验补上边界。

---

## 【问题】
TypeScript 能避免所有错误吗？它的边界在哪里？

## 【回答】
TS 带来了**重构安全、编辑器提示、接口契约、团队协作、错误提前发现**等价值；但也有类型建模和配置学习成本、编译时间、类型体操复杂度、类型与运行时可能漂移的代价。它**不能保证**逻辑正确、后端返回符合声明、所有运行时异常、第三方库实现正确。

---

## 【问题】
什么场景适合用 TypeScript？

## 【回答】
中大型项目、多人协作、公共 SDK、复杂数据流和长期维护代码收益明显；短期脚本或类型变化极少的原型可采用渐进式接入。推荐开启 `strict`，但应结合旧项目迁移计划逐步收紧。从边界开始标注：请求响应、组件 props、公共函数和状态模型；**避免用 `any` 快速消除错误**。

---

## 【问题】
面试时怎么答「TypeScript 解决了什么问题、有什么局限」？

## 【回答】
**30 秒基础回答**：TypeScript 是 JavaScript 的超集，主要通过静态类型检查在编译期发现部分错误，最后编译成 JavaScript 运行。它提升大型项目的重构和协作安全，但类型大多会被擦除，所以不能替代运行时校验，也不能避免所有运行时错误。

**1～2 分钟高级回答**：TypeScript 编译器会解析类型和代码，建立符号与类型关系，进行控制流和赋值检查，再输出目标 JavaScript。它的核心价值是把隐式契约显式化，降低接口变化和重构风险；代价是类型建模、构建耗时和类型复杂度。由于网络输入、用户输入和第三方代码仍在运行时产生，工程上通常在边界用 schema 校验，在内部用 TS 类型约束，不能把编译通过当成运行时正确。
