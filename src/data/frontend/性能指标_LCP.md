【问题】什么是 LCP（Largest Contentful Paint）？

【回答】
LCP（Largest Contentful Paint，最大内容绘制）是指页面加载过程中，**视口中最大的内容元素首次渲染完成的时间点**，是衡量页面加载体验的核心指标之一。


【问题】为什么用 LCP 而不是 FCP？

【回答】
| 对比维度 | FCP（首次内容绘制） | LCP（最大内容绘制） |
|---------|-------------------|-------------------|
| 定义 | 浏览器首次渲染任何内容的时间 | 视口中最大内容元素渲染完成的时间 |
| 反映的体验 | 页面"开始加载了"的信号，解决白屏问题 | 页面"主要内容加载完成"的信号，解决"内容迟迟不出来"的问题 |
| 局限性 | 1. 只能看到"第一个像素"，但这个像素可能只是个小图标或空白背景，用户还是看不到核心内容；<br>2. 很多优化手段可以让 FCP 很快，但核心大图、大文本块迟迟不渲染，用户体验依然很差。 | 1. 直接衡量用户能看到的**主要内容**何时加载完成，更贴近用户真实感知；<br>2. 是目前 Google 认定的核心体验指标，直接影响 SEO 排名。 |

LCP 比 FCP 更能准确反映用户感知到的页面加载速度。


【问题】如何优化 LCP？

【回答】
核心思路：**减少「关键资源加载时间」和「浏览器渲染阻塞」**

### 1. 优化关键资源加载（最直接的优化）

- **优化首屏大图**：压缩图片，提高图片加载优先级
- **优化字体加载**：字体文件压缩；预加载关键字体
- **减少关键请求数量**：合并小的文件，减少 HTTP 请求数；非关键资源懒加载

### 2. 优化服务器响应时间（TTFB）

- 优化后端接口，减少数据库查询、计算时间
- 使用 CDN 加速静态资源分发
- 开启缓存（HTTP 缓存、CDN 缓存）
- 对静态页面使用 SSR/SSG，避免客户端渲染导致的首屏延迟

### 3. 减少渲染阻塞资源

- **内联关键 CSS**：把首屏需要的 CSS 直接内联在 HTML 里，避免额外的请求阻塞渲染
- **非关键 CSS 异步加载**：使用 `media="print"` 或 `rel="preload"` 加载非关键 CSS
- **延迟非关键 JS**：给非必要的脚本加上 `defer` / `async`，避免阻塞 HTML 解析和渲染
- 移除未使用的 CSS/JS，减少解析和执行时间

### 4. 优化浏览器渲染流程

- 避免在 LCP 元素上使用复杂的 JS 操作（如动态修改宽高、背景图）
- 避免在首屏使用大型 JS 框架的客户端渲染，优先 SSR / 静态生成
- 避免长任务阻塞主线程，导致浏览器无法及时渲染 LCP 元素（用 Web Worker 处理重计算逻辑）
