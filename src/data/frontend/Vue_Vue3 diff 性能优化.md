# Vue3 diff 性能优化

## 【问题】
Vue3 为什么比 Vue2 diff 快？

## 【回答】
Vue3 的性能提升主要来自**编译器和运行时协同优化**。

**编译阶段**：

- 通过 **patchFlag** 标记动态节点；
- 通过**静态提升**减少静态 VNode 创建；
- 通过**事件缓存**保持引用稳定；
- 同时利用 **Block Tree** 收集动态子节点。

**运行时 patch 阶段**：

无需递归遍历整棵 VNode 树，而是直接遍历 **dynamicChildren**，并结合 **patchFlag** 对动态内容进行**精准更新**。

## 【问题】
Vue3 Diff 为什么快？

## 【回答】
Vue3 Diff 的优化主要来自**编译器和运行时结合**：

- **编译阶段**：通过 **Block Tree** 和 **PatchFlag** 缩小需要比较的范围。
- **运行时**：针对 **keyed children** 使用**头尾预处理**减少无效比较；再通过 **key 建立节点身份映射**；并利用**最长递增子序列**计算**最少移动路径**，从而减少 DOM 操作。

## 【问题】
Vue3 为什么比 Vue2 快？（综合版：响应式 + 编译 + 运行时）

## 【回答】
**不是单点优化**，而是几层协同的结果：

1. **响应式成本降低**：Proxy 替代 `Object.defineProperty`，并采用**惰性代理**，初始化时不再递归定义全部属性。
2. **编译优化减少运行时 diff**：patchFlag 标记动态节点、静态提升减少 VNode 创建、事件缓存保持引用稳定。
3. **Block Tree 减少比较范围**：把动态节点收集成**扁平化数组**，更新时无需递归遍历整棵 VNode 树。
4. **静态提升减少 VNode 创建**：静态节点只创建一次并复用。

## 【问题】
什么是 Patch Flag？它如何帮助减少运行时比对？

## 【回答】
**Patch Flag（补丁标志）** 是编译器在 VNode 上标记的**动态类型信息**，例如文本、class、style、props 等。运行时 renderer 读取 flag 后，只走**更窄的 patch 路径**去更新被标记的动态内容，而不必遍历比较节点的全部属性。配合 Block Tree 收集的 **dynamicChildren**，运行时能跳过静态节点，实现**精准更新**，这是 Vue3 diff 比 Vue2 更快的关键之一。

## 【问题】
什么是静态提升（Static Hoisting）？为什么能优化性能？

## 【回答】
**Static Hoisting（静态提升）** 把模板中**不变的静态 VNode / 属性提升到渲染函数之外**，在模块初始化时只创建一次并复用，避免**每次 render 都重建静态节点**。由于静态内容不随状态变化，提升后既减少了 VNode 创建开销，也减少了运行时需要比对的节点数量，从而提升渲染性能。

## 【问题】
Block Tree 和 Dynamic Children 是什么？如何缩小比较范围？

## 【回答】
- **Block Tree**：编译器以 **block** 为单位收集其中的**动态子节点**；
- **Dynamic Children**：保存当前 block 下需要关注的**动态节点集合**。

更新时，运行时直接遍历 **dynamicChildren（扁平化的动态节点数组）**，而**无需递归遍历整棵静态 VNode 树**，从而大幅缩小需要比较和 patch 的范围，避免对已确定的静态内容做无谓对比。

## 【问题】
为什么 Vue 模板能比 React JSX 做更多编译优化？

## 【回答】
因为**模板语法限制了表达范围**，编译器能明确知道哪些节点**不会改变**、可以静态提升或标记 flag；而 React 常见的 **JSX 更接近任意 JavaScript**，除非配合额外编译约定，静态性**不总能同样确定**。这是**表达能力与可优化信息量之间的权衡**，并非框架能力绝对高低——Vue 用模板约束换取更多确定性优化，React 用灵活 JS 表达换取自由度。

## 【问题】
Vue 3 编译优化有哪些边界和会退化的场景？

## 【回答】
编译优化增加了**编译器复杂度和运行时分支**，并非任何场景都自动生效。以下情况会**退化到通用路径**，失去部分优化收益：**手写 render 函数、动态组件、`v-html`、或不稳定结构**。验证时应用**编译产物、Vue Devtools 和 Performance** 比较"启用/失去优化"时的 VNode 创建、patch 遍历与更新耗时，确认优化确实生效。

## 【问题】
面试时怎么答「Vue3 编译优化」？（基础版）

## 【回答】
Vue3 通过**编译期标记动态信息**，让运行时**不用遍历整棵 VNode 树**：**静态节点提升**（只创建一次）、**动态节点带 Patch Flag**（走更窄 patch 路径）、**Block Tree 收集 Dynamic Children**（直接遍历动态节点）、**事件处理器可缓存**（Cache Handler 保持稳定引用）。收益来自**模板提供的静态信息**，代价是编译器与运行时复杂度；不是任何场景都能自动获得同样收益，手写 render / `v-html` 等会退化。
