# 索引类型与聚簇索引

## 【问题】
主键索引是一种特殊的唯一索引吗？这句话对不对？

## 【回答】
**正确。主键索引本质上就是「唯一索引 + NOT NULL 约束」**。它满足唯一索引的全部约束（列值不能重复），在此基础上额外要求列值不能为 NULL，因此可以理解为一种特殊的唯一索引。

一句话记忆：**Primary Key = UNIQUE + NOT NULL**。

## 【问题】
主键索引、唯一索引、普通索引三者的区别是什么？

## 【回答】
| 类型 | 是否唯一 | 是否允许 NULL | 一个表能有几个 |
| --- | ---: | ---: | ---: |
| 主键索引 Primary Key | 是 | **不允许** | **1 个** |
| 唯一索引 UNIQUE | 是 | 通常允许 NULL，具体与数据库实现有关 | 多个 |
| 普通索引 INDEX | 否 | 允许 | 多个 |

**一个表最多只能有一个主键，但可以建多个唯一索引和普通索引**。

## 【问题】
聚簇索引的叶子节点存的是什么？「聚簇索引的叶子节点存的是数据记录的内存地址」这句话对不对？

## 【回答】
**错误**。以 InnoDB 为例：

- **聚簇索引（Clustered Index）的叶子节点直接存完整的数据行**，而不是内存地址；
- 数据库记录在磁盘页与 Buffer Pool 中管理，**不存在所谓「直接存一个内存地址」的结构**；
- InnoDB 中**主键索引 ≈ 聚簇索引**，表数据本身就是按主键组织的那棵 B+ 树。

## 【问题】
InnoDB 中什么是回表？为什么会发生回表？

## 【回答】
InnoDB 的两级索引结构决定了查二级索引可能要再查一次主键索引：

```text
主键索引 / 聚簇索引
  叶子节点 → 完整数据行

普通二级索引
  叶子节点 → 索引列 + 主键值
```

**二级索引叶子节点存的是「索引列 + 主键值」而不是完整行**，因此当查询需要的字段不完全被二级索引覆盖时，必须**拿着主键值回到聚簇索引再查一次**，这个过程叫**回表**。能被二级索引完全覆盖、无需回表的情况叫**覆盖索引（Covering Index）**。

## 【考察点】
判断题高频混淆点集中在两个说法上：
1. 「主键索引是一种特殊的唯一索引」→ **对**；
2. 「聚簇索引叶子节点存的是数据记录的内存地址」→ **错**，叶子节点存的是**数据行本身**。
题目默认 InnoDB 语境作答；InnoDB 一定有聚簇索引（无显式主键时会自动选第一个非空唯一索引，或生成 6 字节隐藏 row_id）。
