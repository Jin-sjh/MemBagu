# 装饰器模式

## 【问题】
装饰器可以在运行时动态地给对象添加功能吗？

## 【回答】
**可以，这正是装饰器模式的核心价值**。

> 装饰器模式：**在不修改原对象代码的前提下，动态地给对象增加额外功能**。

通过在原对象外层逐层包裹装饰器对象来叠加能力，包裹动作发生在运行期，可以任意组合、随时增减。

## 【问题】
装饰器模式的基本结构与使用方式是什么？

## 【回答】
调用链示意：

```text
原对象
  ↓ 包一层
日志装饰器
  ↓ 再包一层
权限装饰器
  ↓ 再包一层
缓存装饰器
```

代码示例：

```java
Component c = new ConcreteComponent();

c = new LogDecorator(c);
c = new CacheDecorator(c);
```

最终结构：

```text
Cache(
    Log(
        原对象
    )
)
```

**装饰器与被装饰对象实现同一个接口（Component）**，因此对客户端完全透明——客户端拿到的是一个 `Component`，感知不到它被增强了多少层。典型实践：Java I/O 流（`BufferedInputStream(FileInputStream)`）、Servlet `HttpServletRequestWrapper`。

## 【问题】
装饰器模式和继承相比，区别在哪里？

## 【回答】
| 维度 | 继承 | 装饰器 |
| --- | --- | --- |
| 扩展时机 | **编译期确定**，静态扩展 | **运行期动态**，对象级别 |
| 实现方式 | **父子类的 is-a 关系** | **组合**，持有被装饰对象的引用 |
| 功能叠加 | 每加一种组合就要新增一个子类，**类爆炸** | **多个装饰器自由嵌套**，线性叠加 |
| 灵活性 | 一旦继承关系确定难以更改 | **随时增删某一层装饰** |

核心差异一句话：**继承是编译期的静态增强，装饰器是运行期的组合增强**，符合「合成复用原则（优先组合而非继承）」。

## 【考察点】
判断题：「装饰器模式支持运行时动态增加对象功能」→ **正确**。
易混点：装饰器 ≠ 代理。
- **装饰器**：目的是**给自己加功能**，客户端主动层层包裹，可叠加；
- **代理**：目的是**控制访问**（权限、懒加载、远程调用），通常只有一层，对被代理对象的能力不做扩展。
