# 从资料抽取八股 — 实操指南

本文件是 `bagu-organizer` 的「Mode B — 从资料抽取」的详细参考。当用户输入的不是
聊天讨论，而是**一份外部资料**（粘贴文本 / 本地文件 / 截图 / 网页链接）时，按本指南
把资料里的知识**抽取并蒸馏**成符合 `format-spec.md` 的八股条目。

核心原则：**只做抽取与蒸馏，不做编造**。资料里没有的内容，要么不写，要么明确标注「待补充」。

## 1. 资料接入方式（按类型）

| 资料类型 | 接入方式 | 备注 |
| --- | --- | --- |
| 直接粘贴的文本 / Markdown | 以粘贴内容为准，直接用于抽取 | 最常见 |
| `.md` / `.txt` 本地文件 | `read_file` 读取全文 | 路径由用户提供 |
| 图片 / 截图（`.png/.jpg`） | `read_file` 直接读图（多模态），或请用户贴图 | 读取图中文字与排版后再抽 |
| `.pdf` 文件 | 用 `pdf` skill 提取正文文本后，再按文本处理 | 不要尝试直接 parse 二进制 |
| `.docx` 文件 | 用 `docx` skill 提取文本后，再按文本处理 | 同上 |
| 网页 / 文章链接 | `web_fetch` 抓取正文后按文本处理 | 优先抓取正文，忽略导航/广告 |
| 多个文件 / 多段资料 | 逐个接入，统一归并到同一批抽取任务 | 避免重复 topic |

接入后统一得到「纯文本资料」，进入第 2 步。

## 2. 资料结构化（可借力脚本）

运行 `scripts/extract_candidates.py <资料文件>` 可自动：
- 按 Markdown 标题切分为若干 segment（无标题则按空行分段）；
- 对每个 segment 标记：是否含显式 Q&A（`has_explicit_qa`）、是否疑似算法题
  （`leetcode_flag`）、八股价值分（`eightgu_score`）、以及几条建议提问
  （`suggested_questions`）。

用这个输出快速判断：哪些段落是高价值考点、哪些已经是问答结构、哪些需要「蒸馏」。
注意脚本只是辅助，最终判断与问答撰写由你完成。

## 3. 两种抽取模式

### 3.1 显式问答（资料本身就有 Q&A）

资料里已存在「问/答」配对（如笔记、FAQ、面经、带 `【问题】` 的原文）：
- **忠实保留**原意与关键术语，只做格式归一（统一为 `## 【问题】` / `## 【回答】`）。
- 合并同一概念的不同问法为一条更完整的问答（参考 `format-spec.md` 反模式）。
- 增强块（`【题目链接】`/`【难点分析】`/`【考察点】`/`【衍生问题】`/`【口诀】`/`【代码】`）
  单独成块，不要嵌进 `【回答】`。

### 3.2 讲解型资料（资料是叙述/文章，没有现成问答）

这是「蒸馏」的核心：把一段讲解**反向构造成八股问答**。

步骤：
1. 用脚本给出的 `suggested_questions` 作为提问骨架，按资料内容选 1–4 个最贴切的问法
   （通常覆盖：定义类 / 原理类 / 对比类 / 场景类 / 优缺点类）。
2. 答案**严格从资料原文提炼**，保留关键结论并用 `**加粗**` 突出（解析器据此统计要点数）。
3. 资料里有代码/图示/表格，**原样保留**到对应块（代码进 `## 【代码】`，图示用 `![]()` 链接）。
4. 资料未覆盖但面试常考的点，可加 `## 【衍生问题】` 并标注「待补充」，不要自己编答案。

提问模板（按资料里的 cue 词触发）：
- 定义类：「什么是 X？」「X 是什么？」
- 原理类：「X 的底层原理/实现机制是什么？」
- 对比类：「X 和 Y 的区别是什么？」
- 场景类：「X 在什么场景下使用？」
- 优缺点类：「X 有什么优缺点？」
- 流程类：「X 的完整流程/步骤是什么？」

## 4. 类型判定（type 字段）

- 资料是算法题（含题目链接、函数签名 + 复杂度分析、`leetcode_flag` 命中）→ `type: leetcode`，
  必须包含 `## 【题目链接】` 块。
- 纯概念讲解、无问答结构、用户只想要一份讲解存档 → `type: explain`（正文整篇作为讲解）。
- 其余常规面试问答 → `type: bagu`（默认）。

## 5. 多主题拆分

一份资料常跨多个考点：
- 按 segment / 子标题拆成多个 `(library, category, topic)` 条目。
- 同一 category 下的多个 topic 各自成文件（如 `JavaScript_闭包.md`、`JavaScript_原型与原型链.md`）。
- 若整份资料只讲一个概念（如「闭包」），即使分了多段，也合并进同一个 topic 文件，
  多条 `## 【问题】`/`## 【回答】` 顺次排列。

## 6. 质量约束

- **不编造**：只写资料里有依据的内容；存疑处标注或向用户确认。
- **保真**：术语、代码、公式、复杂度数字保留原文，不擅自「润色」成不准确表述。
- **去重**：写入前先 `scan_entries.py` 看是否已有同类文件，已存在则合并而非新建副本。
- **预览**：落盘前用 Step 7 预览，让用户确认抽取范围与条数（资料量大时尤其重要）。

## 7. 蒸馏示例

资料原文（讲解型）：
> # 防抖与节流
> 防抖（debounce）是在事件触发后等待一段时间，若期间再次触发则重新计时，只执行最后一次；
> 常用于搜索框输入。节流（throttle）是固定时间间隔内只执行一次，常用于滚动、resize。

蒸馏产出（节选）：
```
## 【问题】
防抖（debounce）是什么？适用什么场景？

## 【回答】
防抖是事件触发后**等待一段时间**，若等待期内再次触发则**重新计时**，最终只执行**最后一次**。
常用于**搜索框输入**等「用户停止操作后再执行」的场景。

## 【问题】
节流（throttle）与防抖的区别是什么？

## 【回答】
- **节流**：固定时间间隔内**只执行一次**，适用于滚动、resize 等高频连续触发场景。
- **防抖**：等待期重新触发则重计，只执行最后一次，适用于输入停顿后执行场景。
```
