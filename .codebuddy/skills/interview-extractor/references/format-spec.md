# 面试题目提取格式规范

本文件是 `interview-extractor` skill 的详细参考。SKILL.md 中的格式化步骤应严格遵循此规范，
确保产出文件能被 `src/utils/parser.js` 正确解析并收录进 MemBagu 应用。

## 1. 文件存储位置

```
src/data/面经/面经_<公司><岗位>.md
```

- `面经` 是独立题库库（`src/data/面经/`），不按岗位方向拆分到 AI/frontend/cs-basics。
- 文件名固定以 `面经_` 开头，后接「公司 + 岗位」，如 `面经_字节大模型算法岗.md`、
  `面经_腾讯前端岗.md`。同公司同岗位多篇（不同轮次/不同来源）用后缀区分，
  如 `面经_字节大模型算法岗_秋招.md`。
- frontmatter 的 `category` 固定为 `面经`，与文件名前缀一致。

## 2. Frontmatter（YAML，轻量解析）

解析器为轻量实现，支持 `key: value` 与 `[a, b]` 数组；字符串可用可不用引号。字段如下：

```
---
category: 面经                # 必填，固定为「面经」
topic: <公司><岗位>           # 必填，如「字节大模型算法岗」，与文件名主体一致
type: bagu                    # 固定 bagu（面试题不另设类型）
company: <公司>               # 必填，如「字节跳动」
position: <岗位>              # 必填，如「大模型算法岗」
rounds: [一面, 二面, HR面]     # 可选，本次收录涉及的面试轮次
tags: [面经, <公司>, <岗位>, <方向标签>]  # 可选，数组形式
difficulty: easy | medium | hard          # 可选
created: YYYY-MM-DD           # 必填，创建日期
---
```

- 数组字段务必使用 `[a, b]` 形式，不要用 YAML 多行列表。
- `company` / `position` / `rounds` 为本 skill 新增字段，解析器会原样保留，用于应用内筛选。

## 3. 正文结构

```
# <公司><岗位>面试记录

> 来源：<来源描述，如链接或图片文件名>（可选）

## 【问题】
<第几轮 / 场景 + 问题正文，可多行>

## 【回答】
<回答正文，支持 markdown、代码块、加粗等>
<若资料未给出答案，此处写「回答建议」，并在开头明确标注：>
> 回答建议（资料未提供原文答案，以下为根据公开资料的整理）

## 【问题】
...

## 【回答】
...

## 【衍生问题】        # 可选增强块，资料未覆盖但值得追问的点
...

## 【考察点】          # 可选增强块
...
```

- 每个问题前若来自不同轮次，在 `## 【问题】` 正文内注明轮次，如「一面：请介绍你的项目」。
- 关键结论用 `**加粗**` 突出（解析器据此统计要点数）。

## 4. 解析器关键行为（务必遵守）

来自 `src/utils/parser.js` 的实测行为：

1. 以 `## 【问题】` / `## 【回答】` 标记问答块；同行之后的内容算作该块正文。
2. 任一其他 `【xxx】` 增强块出现时，会**结束当前回答的收集**，且增强块独立存在、不计入 answer。
   因此 `【衍生问题】` 等应单独成块，不要写在 `【回答】` 内部。
3. `title` 取第一个 `# ` 行（应为「公司岗位面试记录」）。
4. `category`/`topic` 优先取 frontmatter；缺省时回退为文件名 `category_topic` 的下划线拆分。
5. `keyPointsCount` 由回答中 `**加粗**` 数量统计，故关键结论建议用 `**加粗**` 突出。
6. 文件必须位于 `src/data/<library>/` 下，且不能是 `README.md`，否则不会被收录。

## 5. 命名与去重反模式

- 不要创建 `面经_xxx2.md` 这类副本；若该公司+岗位的面经已存在，合并进原文件。
- `category` 必须为 `面经` 且与文件名前缀一致，否则应用内展示与解析会错位。
- 同一问题在不同来源重复出现时，合并为一条更完整的问答，而非逐字重复堆叠。
