# MemBagu 项目长期记忆

## 核心工作流约定（强制）

### 八股题统一走 bagu-organizer skill 沉淀
- 用户在这个项目里**发八股题 / 八股笔记 / 面经资料**（粘贴文本、md、截图、链接都算）时，
  默认动作不是「在对话里回答完就结束」，而是**调用 `bagu-organizer` skill 走完流程并落盘**到
  `src/data/<library>/<category>_<topic>.md`。
- 2026-09-14 Jin 明确：「我发这种题就用 bagu skill 处理沉淀」。
- 落盘规范要点（详见 `.codebuddy/skills/bagu-organizer/references/format-spec.md`）：
  - frontmatter 的 `category` 必须与文件名前缀一致；`created` 保留首次日期不覆盖。
  - 正文结构 `## 【问题】` + `## 【回答】`；`【考察点】` `【衍生问题】` 等增强块单独成块，
    不要嵌进 `【回答】` 里（解析器会提前结束回答收集）。
  - **已存在同名条目就合并，禁止建 `xxx2.md` 副本**；合并时只增补、不删既有内容。
  - 关键结论用 `**加粗**`（解析器据此统计 keyPointsCount）。
- 对话里照样给简答（用户要背的版本），同时把内容沉淀进知识库，两件事一起做。

### 大部头资料（200 页以上 PDF / 长文）的沉淀流程
2026-09-15 用这套流程把 405 页《AI Agent 面试全攻略》一次性落库（132 新条目 / 212 组问答），可复用：
1. anaconda `fitz` 提取全文 → 按页切分为若干片段（`.tmp/M0x*.txt`），**不要**一次性塞进主上下文。
2. 用 ` textract README.md `Creator 概览现行 AI 库，给每个子代理一份「**只允许触碰的已有文件**」白名单，避免并行写冲突。
3. 派子代理并行蒸馏 + 落盘（每批 1~2 个模块），prompt 里写死：category 必须等于文件名前缀、
   增强块不得嵌进【回答】、关键结论加粗、**沿用被合并文件的原 frontmatter 值**。
4. 落盘后跑校验脚本复核（见本文件下方「校验脚本」），再清理临时文件。
5. 中文 PDF 若标题出现乱码（如「%ULGJH模式」= Bridge 模式），是字体缺 ToUnicode，按语义还原后写入。

### 讲解型 Wiki 目录整批沉淀流程（2026-09-21 用这套把桌面 wiki 105 页一次入厍，109 文件 / ~380 问答）
与「单个大部头 PDF」的区别是：源已经是拆好的知识页，**关键工作在于映射与防冲突**，不再需要切片进给。
1. 先列全部源文件 + 大小，把 Non-知识页挑出来（README/知识地图/学习状态/_reviews 审查记录/纯问题索引），
   这几类不入库并在汇报里说明。
2. **主代理亲自定「源文件 → 目标 category_topic.md」1:1 映射表**， category 优先复用
   `src/data/frontend` 已有前缀，NestJS / 工程化 / 性能 / 前端架构 等新 category 集中在同一批里，
   规则一并写进每个子代理的 prompt，它们不允许自选文件名。
3. 给每个子代理配一份「只允许创建/修改的目标文件白名单」，同一目标文件绝不分配给两个子代理，
   这样并行写不会互相覆盖。每波 7~8 个、每个 4~13 个源文件，分波跑。
4. prompt 里写死：category 必须等于文件名前缀、topic 等于后缀（含空格/括号照抄）、
   增强块不得嵌进【回答】、关键结论加粗、已存在文件沿用原 created 并在末尾追加（重复问题用
   `**补充：**` 追加而非新增副本）、禁止 xxx2.md。
5. 落盘后用临时脚本校验（见下）+ 抽查 2~3 个文件内容，再删临时脚本。

### 校验脚本（临时用，用完即删）
核对 frontmatter category/topic 与文件名一致、`## 【问题】` 与 `## 【回答】` 数量配对、答案不为空、答案含加粗。
用 `node` 写校验比 Python 稳：本机 Git Bash 对 `-c "..."` 里的 `\s` 有转义吞字符问题，会导致正则失效、误报一堆。
